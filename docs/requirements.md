# CartMate — MVP 要件 v1.2

この文書は、MVP でシステムがどう振る舞うかを定めます。実現方法（データ構造、Security Rules、アルゴリズムの詳細）は [design/](design/) の設計資料にまとめています。

## 1. 目的
家族が買い物先ごとに必要な商品だけを確認し、リアルタイムに追加・チェックできる Android アプリを作る。商品を追加するとき、過去の購入履歴から購入周期を予測し、必要になりそうな商品を提案する。日常の操作はシンプルに保つ。

## 2. 基本要件
- Android ネイティブアプリ。Kotlin + Jetpack Compose。
- Google アカウントでログインし、アプリ独自の家族グループに招待して共有する。Google ファミリーグループのメンバー情報には依存しない。
- 1人のユーザーが参加できる家族グループは1つだけ。
- Cloud Firestore でリスト・商品・チェック状態をリアルタイムに同期する。自前のサーバーは運用しない。
- 買い物リストの名前はユーザーが自由に決める（例: スーパー、イオン、薬局）。店舗種別や購入場所のマスタは作らない。
- 商品は原則1つのリストに追加する。別の場所で買った場合も、元のリスト上で手動でチェックする。
- 商品を追加するたびに、新しい買い物項目を作る。チェック済みの項目は再利用しない。
- 数量・単位・備考を指定できる。商品名だけでも追加できる（数量1・単位「個」になる）。
- リストと商品には公開範囲（共有／プライベート）がある。プライベートなものは、登録した本人にだけ表示する（§3.4）。
- チェックを取り消せる（Undo）。未購入の項目は、商品名・数量・単位・備考を編集でき、誤って追加したものは削除できる。
- 店内など電波の弱い場所でも、追加・チェック・Undo・削除ができる。接続が戻ると家族に共有される。
- サジェストは、リスト詳細の商品追加欄にフォーカスして開くボトムシートの中にだけ表示する。独立したサジェスト画面は作らない。
- 購入周期の予測は、同じ商品を3日以上買ってから始める。
- 購入周期は、直近の購入間隔の中央値など、外れ値に強い方法で推定する。
- いつもより早い再購入を検知し、追加を妨げない注意を表示する。
- 商品名の表記ゆれを扱う。意味の違う商品を誤ってまとめないよう自動では確定せず、ユーザーが選ぶ。
- 購入履歴は、買い物リストを削除しても残す。

### 用語
- **チェック**: 項目を「買った（カゴに入れた）」状態にする操作。チェックはカゴに入れた時点で行うのが普通だが、別の場所で買って帰宅後にチェックしてもよい。
- **のこり / 完了**: 画面上は、まだチェックしていない項目を「のこり」、チェックした項目を「完了」と表記する（「未購入」はカゴに入れた時点の実態に合わないため使わない）。Snackbar などの操作の結果は「チェックしました」「チェックを外しました」と表記する。この文書では、チェックしていない項目を「未購入の項目」と呼ぶ。
- **購入**: 予測に使う記録。チェックすると1件の購入が記録され、Undo すると無効になる。
- **公開範囲**: 「共有」（家族全員に表示）か「プライベート」（登録した本人にだけ表示）。リストと商品のそれぞれにある。

## 3. 画面と操作

### 3.1 リスト一覧
- 上部のバーにはアプリ名「CartMate」だけを表示する。プロフィールや設定への導線は置かない。
- 家族のリストを、2列のカードで並べる。カードには、リスト名、備考（あれば）、件数、進捗バーを表示する。リストや商品ごとの装飾アイコンは表示しない。
  | 状態 | 件数の表示 | 進捗バー |
  |---|---|---|
  | 未購入の商品がある | 「N 件 のこり」（数字をブランドカラーで大きく） | 完了の割合 |
  | 未購入が0件で、購入の記録もない（新しく作ったリストなど） | 「0 件 登録なし」 | 空 |
  | 未購入が0件で、購入の記録がある（買い終わった） | 「0 件 買い終わった！」 | いっぱい |

  件数と進捗は、閲覧している本人に見える項目だけで数える。完了の割合は、のこりの件数と直近24時間に完了した件数から求める。購入の記録は、予測と同じく直近365日分で判定する。
- 共有のリストには家族のメンバーのアバターを、プライベートのリストには鍵アイコンを表示する。「共有」という表示は出さない（共有が標準のため）。
- リストが1件以上あるときは、上部に「長押しで並び替えができます」と表示する。
- リストはロングタップで持ち上げ、ドラッグで並べ替えられる。並び順は家族で共有する。TalkBack では、カスタムアクション「前へ移動」「後ろへ移動」で並べ替えられる。
- タップすると詳細に移る。
- 右下の「＋ リスト作成」ボタンから、ボトムシートでリストを作成する。リスト名（必須）、公開範囲（「共有リスト」か「プライベート」。初期値は共有）、メモ（任意。リストの備考）を入力する。新しいリストは末尾に追加する。リストの公開範囲は、作成したあとは変更できない。
- リストが1件もないときは、画面中央に「リストがありません」「最初の買い物リストを作成しましょう」と「＋ リストを作成する」ボタンを表示する。
- リスト名と備考の変更、リストの削除は、リスト詳細の上部のメニューから行う（§3.2）。

### 3.2 リスト詳細
- 上部のバーに、戻るボタン、リスト名、メンバーのアバター（プライベートのリストでは鍵アイコン）、メニュー（「リストを編集」「リストを削除」）を置く。
- **リストの編集と削除**
  - 「リストを編集」で、リスト名と備考を変更できる。変更しても、過去の購入の記録に残したリスト名は書き換えない（§4.4）。
  - 「リストを削除」は、未購入が0件のリストだけで選べる。確認ダイアログを経て削除する。最後の項目をチェックした直後に自動で削除することはしない（誤操作や Undo と競合しないように）。
  - 削除したリストでも、未購入の項目が残っている間は一覧に表示する（削除と同時に家族が項目を追加した場合や、削除後に Undo した場合に、項目が見えなくならないように）。項目がなくなると再び表示されなくなる。
  - リスト削除はオンラインのときだけ行える。
- リスト名の下に「買い物進捗」として、「のこり N件 / M完了」のバッジと進捗バーを表示する。
- 未購入の項目と、直近24時間にチェックした項目を、並び順に表示する。新しい項目は末尾に追加する。その上に「カードをタップして購入完了」と案内を表示する。
- 項目は1件ずつカードで表示し、カードの間を少し空ける。
- 各カードは、1行目に商品名と数量・単位（「2本」のような小さなバッジ）、2行目に備考を表示する（備考がなければ2行目は表示しない）。共有のリストにあるプライベートな項目には、鍵アイコンを付ける。
- 未購入の項目をタップするとチェックし、チェック済みの項目をタップするとチェックを外す。チェックボックスは表示しない。
- チェックした項目は別の場所に移さず、元の位置のまま、カードの背景を薄い色にし、商品名を打ち消し線と薄い文字で示す。2行目にはチェックの印と、チェックした人と時刻を表示する（例: 「✓ 花子 10:02」）。チェックから24時間が過ぎると表示しなくなる。
- 項目をチェックすると、他の家族の端末でもその項目が完了の表示になる。
- 行の右端にボタンを置く。未購入の項目は「編集」「削除」のアイコンボタン、チェック済みの項目は「元に戻す」ボタン（チェックを外す）。スワイプでも同じ操作ができる。チェック済みの項目は、画面を移動したあとでもここからチェックを外せる。
- 項目はロングタップで持ち上げ、上下にドラッグして並べ替えられる（チェック済みの項目も含む）。並び順は家族で共有する。左右のスワイプとは指の向きで区別する。
- TalkBack では、項目のカスタムアクション「上へ移動」「下へ移動」で並べ替えられる。項目が1つもないときは「購入予定の商品はありません」と表示する。
- チェックの直後に、Undo できる Snackbar（約5秒）を表示する。
- チェックと Undo は家族の誰でも行える（プライベートな項目は本人だけが見えるので、本人だけが行える）。
- **スワイプ操作**: 「→ チェック、← 取り消し」で統一する。

  | 場所 | → スワイプ | ← スワイプ |
  |---|---|---|
  | 未購入の項目 | チェックする | 項目を削除する |
  | チェック済みの項目 | なし | チェックを外す |

  - 削除した直後は「元に戻す」付きの Snackbar を表示する。元に戻した項目は、削除する前の位置に戻る。
  - TalkBack では、項目をダブルタップするとチェックの切り替えになる。ほかの操作はボタンで行える。
- **項目の編集**
  - 未購入の項目の「編集」ボタンを押すと、商品詳細入力画面を編集モード（タイトル「商品の編集」、確定ボタン「更新する」）で開き、商品名・数量・単位・備考を変更できる。公開範囲は表示するだけで、変更できない。
  - 編集をやめると（✕ か戻るキー）、変更せずにリスト詳細に戻る。商品追加欄に入力途中の商品名があれば、そのまま残る。
  - チェック済みの項目は編集できない（購入の記録と内容を食い違わせないため）。編集したい場合は、チェックを外してから行う。
  - 編集中に他のメンバーがその項目をチェックまたは削除した場合は、変更を反映せず、その旨を表示する。
- **商品の追加**
  - 画面下部に商品追加欄（「商品名を入力して追加...」）を常に表示する。
  - 商品追加欄にフォーカスすると、サジェストのボトムシートが開く。シートの上部に商品名の入力欄があり、ソフトキーボードに追従する。背面のリスト詳細は半透明の幕で覆う。シートを閉じている間は、サジェストを表示しない。
  - シートを閉じると（戻るキーや幕のタップ）、入力途中の商品名は商品追加欄に残る。
  - 未入力のときは、購入時期が近い商品を提示する（§4.3）。入力中は、過去の商品名から補完候補を表示する（購入周期の条件は使わない）。候補は「履歴」「予測」などに分けず、1つの一覧で表示する。
  - 入力中は、候補の上に「数量を設定して追加」を表示する（商品名は含めない）。タップすると、入力した商品名で商品詳細入力画面に進む。
  - 候補の名前の部分をタップすると、その候補の内容（商品名、前回の数量・単位）を引き継いで、商品詳細入力画面に進む。
  - 候補の右端の「＋」をタップすると、前回の数量・単位（なければ数量1・単位「個」）で、すぐにリストの末尾に追加する。
  - 商品名を入力して IME の Enter/Done を押すと、数量1・単位「個」・備考なしで、すぐにリストの末尾に追加する。シートは閉じず、入力欄を空にしてキーボードを開いたままにし、続けて次の商品を入力できる。
  - 「＋」と Enter による追加の公開範囲は、そのリストで直前に選んだ公開範囲を引き継ぐ（§3.4）。
  - 未購入リストにすでにある商品の補完候補には「追加済み」と表示する。追加はできる。
  - いつもより早い再購入の場合（§4.5）、その商品の補完候補に前回の購入日と普段の周期を控えめに表示する。
- **商品詳細入力画面**
  - 上部に ✕（閉じる）と「商品の詳細入力」。その下に追加先（例: 「追加先: スーパー（共有リスト 3人）」）を表示する。
  - 商品名（編集できる）。購入の記録があれば、その下に前回の数量・購入日・普段の周期を表示する（例: 「前回: 1パック（10/18 購入・約14日ごと）」）。いつもより早い再購入の場合は、ここで知らせる（§4.5）。
  - 数量: 大きな数字と「−」「＋」のボタン。初期値は1。
  - 単位: 「個」「本」「パック」「袋」などの候補と自由入力。候補から来た場合は前回の単位、それ以外は「個」を初期値にする。単位は空欄でもよい。
  - 公開範囲: 共有のリストでは「全員に共有」「自分のみ」を選ぶ。初期値はそのリストで直前に選んだ公開範囲。「※ 登録後に公開範囲を変更することはできません」と注記する。プライベートのリストでは表示しない（すべてプライベートになる）。
  - 備考（任意・複数行）。過去にその商品に付けた備考を候補として表示する。
  - 入力した商品名が既存の商品と似ている場合（§4.2）、「『牛乳』と同じ商品として記録する」という選択肢を表示する。初期状態は未選択。
  - 最下部の「リストに追加する」で、リストの末尾に追加してリスト詳細に戻る。✕ か戻るキーで閉じると、追加せずにサジェストのシートに戻る（入力した商品名は残る）。
- **他のメンバーによるチェックの通知**（二重購入に気づくため）
  - 自分がチェックした項目を他のメンバーが先にチェックしていた場合、「牛乳は 花子さんが 10:02 にチェック済みです」と表示する。この場合、購入は1件だけ記録される。
  - リスト詳細を開いている間に、他のメンバーがこのリストの項目をチェックしたら、「花子さんが牛乳をチェックしました」と表示する。約3秒以内の複数のチェックは1件にまとめる（例: 「花子さんが牛乳ほか2件をチェックしました」）。
  - 画面を開いた時点ですでにチェック済みだった項目は通知しない。
  - 自分の Undo Snackbar と重なった場合は、Undo Snackbar を先に表示する。
  - オフラインの間は他のメンバーのチェックが届かないため、通知は接続が戻るまで遅れる。

### 3.3 オフライン時の振る舞い
- オフラインの間は、上部のバーの直下に「オフライン表示中（変更は再接続時に同期されます）」と表示する。表示中も、キャッシュ済みのリストの閲覧・操作は通常どおり行える。
- オフラインでもできる操作: リスト・項目・履歴の閲覧、項目の追加、リストの作成、チェック、Undo、未購入の項目の削除。
- オフラインでできない操作: リストの削除、家族の作成・参加、招待の発行、商品の統合。操作しようとした場合は理由を表示する。
- オフラインでチェックした項目は、その場でチェック済みとして表示し、家族に共有されるまで「未同期」マークを付ける。アプリを閉じても失われず、接続が戻ると自動で共有される。
- オフライン中に追加した項目なども、共有されるまで「未同期」マークを付ける。
- 共有されないまま7日を過ぎたチェックや、共有の前に家族から外された場合など、反映できなかった変更は「牛乳のチェックを反映できませんでした」のように知らせる。

### 3.4 公開範囲
- **リスト**: 作成するときに「共有」か「プライベート」を選ぶ（初期値は共有）。作成したあとは変更できない。プライベートのリストは、作成した本人にだけ表示する。
- **商品（項目）**: 共有のリストでは、追加するときに「全員に共有」か「自分のみ」を選ぶ。登録したあとは変更できない。プライベートのリストの項目は、すべてプライベートになる。
- プライベートな項目は、登録した本人にだけ表示する。他のメンバーの画面では、件数・進捗・サジェスト・チェックの通知のいずれにも現れない。
- プライベートな項目の購入の記録も、本人にだけ見える。他のメンバーの周期の予測やサジェストには使わない。本人の予測には、共有とプライベートの両方の記録を使う。
- **直前の公開範囲の引き継ぎ**: 共有のリストでは、リストごとに直前に選んだ公開範囲を覚えておき、次の追加の初期値にする。
  - 初回の追加では「共有」を初期値にする。
  - 商品詳細入力画面で選んで追加すると、その公開範囲がそのリストの次回以降の初期値になる。
  - Enter による追加と、候補の「＋」による追加は、直前の公開範囲をそのまま使う（初期値を変えない）。
  - 覚えておくのはアプリを起動している間だけで、アプリを起動し直すと「共有」に戻る。
- 共有のリストにあるプライベートな項目には、鍵アイコンを付ける。プライベートのリストでは、項目ごとの鍵アイコンは付けない（すべてプライベートのため）。

### 3.5 家族共有・設定
- Google アカウントでログインする。
- 家族グループを作成する。作成した人がオーナーになる。
- **招待**
  - 家族のメンバーなら誰でも招待を発行でき、Android の共有シートで送る。文面には招待リンクと招待コードの両方を含める。
  - 招待コードは10文字（読み間違えやすい文字を含まない）で、24時間有効、1回だけ使える。1人に1つ発行する。発行したコードは、家族のメンバーが取り消せる。
  - アプリが入っている端末で招待リンクを開くと、アプリが起動して「○○さんの家族に参加しますか？」と確認する。承認するまで参加しない。ログインしていない場合は、ログイン後にこの確認に戻る。
  - アプリが入っていない端末で招待リンクを開くと、ストアへの案内と招待コードを表示するページが開く。
  - アプリ内で招待コードを入力しても参加できる。
- 家族のメンバー一覧を確認できる。
- オーナーは、自分以外のメンバーを家族から削除できる。本人による脱退とオーナーの引き継ぎは MVP の対象外。
- **商品の統合**: 商品を選んで「別の商品に統合」または「統合を解除」できる。統合すると、両方の購入履歴を合わせて周期を計算する。
- サジェストの閾値などの設定項目は設けない。

## 4. 購入履歴・予測

### 4.1 購入の記録
- 購入日は、端末でチェックした日とする（オフラインでチェックして後から共有された場合も、チェックした日）。商品を登録した日時とは区別する。
- 購入の記録には、商品、購入時の商品名、数量・単位・備考、公開範囲、購入時のリスト名、チェックした日時とチェックした人、元の買い物項目を残す。
- リストを削除しても購入の記録は残る。
- Undo すると購入の記録は無効になり、予測に使われなくなる。
- 同じ項目を複数の端末が同時にチェックしても、購入は1件しか記録されない。
- 同じ項目を Undo してから再びチェックした場合、購入は1件として記録し直す。

### 4.2 商品の同一性
- 次の差だけの商品名は、自動で同じ商品として扱う: Unicode 正規化（全角・半角を含む）、前後の空白、連続した空白、英字の大文字・小文字。
- それ以外の似た名前（「牛乳」と「牛乳 1L」、「ミルク」と「みるく」など）は候補として示すだけで、自動ではまとめない。ユーザーは、商品詳細入力画面の選択肢（§3.2）か商品の統合（§3.5）でまとめられる。
- 「ぎゅうにゅう」と「牛乳」のように読みでしか結び付かない名前は、候補として示せない。商品の統合でまとめる。
- 予測では、まとめた商品の購入記録を合算する。入力した商品名もそのまま残す。

### 4.3 購入周期と時期が近い商品の提案
- 同じ日の複数回の購入は、1回として数える。
- 購入した日が3日未満の商品は、周期を予測しない。
- 購入日を時系列に並べて隣り合う間隔を求め、直近最大10個の間隔の中央値を推定周期とする。
- 経過率 = 最後に購入してからの日数 / 推定周期。
- 未入力でフォーカスしたときは、経過率が80%以上300%以下の商品を、経過率の高い順に最大10件提示する。300%を超えた商品は、買うのをやめたとみなして提示しない。
- 各候補には「約14日ごと・最後は16日前」のような補足を表示する。
- 家族のいずれかの未購入リストにすでにある商品は提示しない。
- 予測は参考情報であり、商品を自動でリストに追加することはしない。
- 予測には直近365日の購入記録を使う。そのため、周期がおよそ180日を超える商品は予測されない。

### 4.4 リスト名と商品の関連
- 購入の記録に、購入時のリスト名を残す。リスト名を変更しても、記録に残したリスト名は書き換えない。そのため、名前を変えた直後は、そのリストで提示する候補が少なくなることがある。
- 同じ名前の過去のリストで買った商品を、優先して候補にする。
- 名前が違うリストでも（「スーパー」と「イオン」など）、過去に買った商品の重なりが大きければ関連するリストとみなし、そのリストで買った商品も候補にする。どちらかのリストの購入商品が少なく判定できない場合は、関連付けない。
- **周期の計算**には、リストに関係なく家族全体の購入記録（自分に見えるもの。§3.4）を使う。**そのリストで提示する候補の選択**にだけ、リストの関連を使う。
- 同じ名前のリストの履歴も、関連するリストもない場合（新しい名前のリストなど）は、時期が近い商品を提示せず、「商品名を入力すると候補が出ます」とだけ表示する。

### 4.5 早すぎる再購入の注意
- 経過率が50%未満の商品は、サジェストの補完候補と商品詳細入力画面で、前回の購入日と普段の周期を控えめに表示する（例: 「前回 10/18 に購入・いつもは約14日ごと」）。
- Enter で候補を選ばずに追加した場合は、注意を表示しない（連続入力を止めないため）。
- 注意は表示するだけで、追加を妨げない。
- 購入した日が3日未満の商品や、購入間隔のばらつきが大きく周期が不安定な商品には表示しない。

## 5. データの扱い
- 家族ごとのデータは、その家族のメンバーだけが読み書きできる。プライベートなリスト・項目・購入の記録は、登録した本人だけが読み書きできる。
- 家族グループ、購入の記録、商品は削除しない。リストは削除しても、購入の記録から参照できるよう内部的には残す。
- 項目の物理的な削除は、未購入の項目に限る。

データ構造の詳細は [design/data-model.md](design/data-model.md) を参照。

## 6. リアルタイム同期・競合
- 家族のリストと項目の変更は、オンラインの端末にリアルタイムに反映される。
- チェックと購入の記録は、1つの操作として同時に成立する。片方だけが反映された状態にはならない。
- 複数の端末が同時に操作した場合の結果は次のとおり。

  | 状況 | 結果 |
  |---|---|
  | 2人が同じ項目を同時にチェック | 先にチェックした人のチェックが残り、もう一方には先にチェックした人と時刻を表示する |
  | 他のメンバーがすでに Undo した項目を Undo | 「すでにチェックが外されています」と表示する |
  | チェックと削除が同時 | 先に行われた方が有効になる。チェック済みの項目は削除されない |
  | リスト削除と項目追加が同時 | 項目は失われず、リストは一覧に表示されたままになる |
  | 使用回数1の招待コードで2人が同時に参加 | 1人だけが参加できる |

## 7. 非機能要件
- Android 端末で片手で操作しやすい UI、IME 操作、アクセシビリティ、読みやすい文字サイズ（文字サイズ200%でも操作できる）。
- 見た目は淡いライラック（`#FFF7FF`）を背景にし、ブランドカラーはライラックパープル（`#6B4E8C`）とする。完了やチェックの表示を含め、緑は使わない。端末がダークモードでも明るい配色のまま表示する。配色・文字・余白・角丸の値は [design-tokens.md](design-tokens.md) に従う。
- 起動・リスト表示・チェック操作が軽快であること。
- 家族グループの外からはアクセスできない。招待コードは十分な乱数・期限・使用回数の制限を設ける。改造したクライアントからのアクセスを抑えるため、Firebase App Check を使う。
- Firestore の読み取り数が増えすぎないよう、購読の範囲と履歴の取得件数を限定する。
- サジェストの計算は端末上で Kotlin で行う。外部の AI API は使わない。

## 10. 受け入れ条件
- 家族2人が、別々の Google アカウントで同じ家族グループに参加できる（招待リンクと招待コードのどちらでも）。
- 一方が追加・チェック・Undo・削除した内容が、オンラインのもう一方の端末に速やかに反映される。
- 「スーパー」「薬局」など任意の名前のリストを作成でき、各リストにはそのリストの商品だけが表示される。リスト名と備考はあとから変更できる。
- 商品名で Enter を押すとすぐに登録され（数量1・単位「個」）、シートを開いたまま連続して追加できる。
- 「数量を設定して追加」または候補の名前のタップから商品詳細入力画面に進み、数量・単位・公開範囲・備考を指定して登録できる。
- 商品追加欄にフォーカスしてサジェストのシートを開くまでは、サジェストが表示されない。
- 同じ商品を買った日が2日までは周期のサジェストを出さず、3日目以降に予測を始める。
- 同じ商品の別表記をユーザーが紐付けられ、統合した購入記録で周期を計算できる。
- 同じ名前のリストと、商品の傾向が似た別名のリストの購入記録を、候補の選択に活用できる。
- いつもより早い再購入のときに注意が出て、利用者はそのまま登録できる。
- リストを削除しても、購入記録と予測に必要な情報が残る。
- 同時にチェックしても購入記録が重複せず、Undo すると予測から除外される。
- 2人が同じ項目をチェックすると、後からチェックした人に、先にチェックした人と時刻が表示される。
- オフラインでチェックした項目が、アプリを閉じても失われず、接続が戻ると家族の端末に反映される。購入日はチェックした日になる。
- 未購入の項目を ← スワイプで削除でき、「元に戻す」で復元できる。
- リストと項目をロングタップからのドラッグで並べ替えられ、並び順がもう一方の端末にも反映される。
- 未購入の項目の「編集」ボタンから、商品名・数量・単位・備考を変更できる。
- 項目のタップでチェックを切り替えられる。
- プライベートなリストと、共有のリストに追加したプライベートな項目は、もう一方の端末に表示されない。その購入記録は、もう一方の予測とサジェストに使われない。
- 共有のリストで「自分のみ」を選んで追加すると、そのリストでの次の Enter・「＋」による追加もプライベートになる。
