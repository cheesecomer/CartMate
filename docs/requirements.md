# CartMate — MVP 要件 v1.3

この文書は、MVP でシステムがどう振る舞うかを定めます。実現方法（データ構造、Security Rules、アルゴリズムの詳細）は [design/](design/) の設計資料にまとめています。

## 1. 目的
家族が買い物先ごとに必要な商品だけを確認し、リアルタイムに追加・チェックできる Android アプリを作る。商品を追加するとき、過去の購入履歴から購入周期を予測し、必要になりそうな商品を提案する。日常の操作はシンプルに保つ。

## 2. 基本要件
- Android ネイティブアプリ。Kotlin + Jetpack Compose。
- Google アカウントでログインし、アプリ独自の家族グループに招待して共有する。Google ファミリーグループのメンバー情報には依存しない。
- 1人のユーザーが参加できる家族グループは1つだけ。
- Cloud Firestore でリスト・商品・チェック状態をリアルタイムに同期する。常時動く自前のサーバー（VM・コンテナ）は運用しない。サーバー側の処理が必要なときは、サーバーレスの関数（Cloud Functions）に限る（AI による名寄せの候補の判定だけ。§4.2）。
- 買い物リストの名前はユーザーが自由に決める（例: スーパー、イオン、薬局）。店舗種別や購入場所のマスタは作らない。
- 商品は原則1つのリストに追加する。別の場所で買った場合も、元のリスト上で手動でチェックする。
- 商品を追加するたびに、新しい買い物項目を作る。チェック済みの項目は再利用しない。
- 数量・単位・備考を指定できる。商品名だけでも追加できる（数量1・単位「個」になる）。
- リストと商品には公開範囲（共有／プライベート）がある。プライベートなものは、登録した本人にだけ表示する（§3.4）。
- チェックを取り消せる（Undo）。未購入の項目は、商品名・数量・単位・備考を編集でき、誤って追加したものは削除できる。
- 店内など電波の弱い場所でも、追加・チェック・Undo・削除ができる。接続が戻ると家族に共有される。
- サジェストは、リスト詳細の商品追加欄にフォーカスして開くボトムシートの中にだけ表示する。独立したサジェスト画面は作らない。
- 購入周期の予測は、同じ商品を3日以上買ってから始める。
- 購入周期は、直近の購入間隔の中央値など、外れ値に強い方法で推定する。
- いつもより早い再購入を検知し、追加を妨げない注意を表示する。
- 商品名の表記ゆれを扱う。意味の違う商品を誤ってまとめないよう自動では確定せず、ユーザーが選ぶ。
- 購入履歴は、買い物リストを削除しても残す。

### 用語
- **チェック**: 項目を「買った（カゴに入れた）」状態にする操作。チェックはカゴに入れた時点で行うのが普通だが、別の場所で買って帰宅後にチェックしてもよい。
- **のこり / 完了**: 画面上は、まだチェックしていない項目を「のこり」、チェックした項目を「完了」と表記する（「未購入」はカゴに入れた時点の実態に合わないため使わない）。Snackbar などの操作の結果は「チェックしました」「チェックを外しました」と表記する。この文書では、チェックしていない項目を「未購入の項目」と呼ぶ。
- **購入**: 予測に使う記録。チェックすると1件の購入が記録され、Undo すると無効になる。
- **公開範囲**: 「共有」（家族全員に表示）か「プライベート」（登録した本人にだけ表示）。リストと商品のそれぞれにある。

## 3. 画面と操作

### 3.1 リスト一覧
- 上部のバーには、アプリ名「CartMate」と、右端に自分の Google アカウントのアバターを表示する。アバターをタップすると家族画面（§3.5）を開く。それ以外の設定への導線は置かない。
- 家族のリストを、2列のカードで並べる。カードには、リスト名、備考（あれば）、件数、進捗バーを表示する。リストや商品ごとの装飾アイコンは表示しない。
  | 状態 | 件数の表示 | 進捗バー |
  |---|---|---|
  | 未購入の商品がある | 「N 件 のこり」（数字をブランドカラーで大きく） | 完了の割合 |
  | 未購入が0件で、購入の記録もない（新しく作ったリストなど） | 「0 件 登録なし」 | 空 |
  | 未購入が0件で、購入の記録がある（買い終わった） | 「0 件 買い終わった！」 | いっぱい |

  件数と進捗は、閲覧している本人に見える項目だけで数える。完了の割合は、のこりの件数と直近24時間に完了した件数（前回の買い物を片付けたリストでは、片付けたあとの完了だけ。§3.2）から求める。購入の記録は、予測と同じく直近365日分で判定する。
- プライベートのリストには鍵アイコンを表示する。共有のリストには何も付けない（共有が標準のため）。家族のメンバーはどのリストでも同じなので、カードにメンバーのアバターは出さず、リスト名の表示を優先する（メンバーは家族画面で確認する）。
- リストが1件以上あるときは、上部に「長押しで並び替えができます」と表示する。
- リストはロングタップで持ち上げ、ドラッグで並べ替えられる。並び順は家族で共有する。TalkBack では、カスタムアクション「前へ移動」「後ろへ移動」で並べ替えられる。
- タップすると詳細に移る。
- 右下の「＋ リスト作成」ボタンから、ボトムシートでリストを作成する。リスト名（必須）、公開範囲（「共有リスト」か「プライベート」。初期値は共有）、メモ（任意。リストの備考）を入力する。新しいリストは末尾に追加する。リストの公開範囲は、作成したあとは変更できない。
- リストが1件もないときは、画面中央に「リストがありません」「最初の買い物リストを作成しましょう」と「＋ リストを作成する」ボタンを表示する。
- リスト名と備考の変更、リストの削除は、リスト詳細の上部のメニューから行う（§3.2）。

### 3.2 リスト詳細
- 上部のバーに、戻るボタン、リスト名（プライベートのリストでは鍵アイコンを付ける）、メニュー（「リストを編集」「リストを削除」）を置く。
- **リストの編集と削除**
  - 「リストを編集」で、リスト名と備考を変更できる。変更しても、過去の購入の記録に残したリスト名は書き換えない（§4.4）。
  - 「リストを削除」は、未購入が0件のリストだけで選べる。確認ダイアログを経て削除する。最後の項目をチェックした直後に自動で削除することはしない（誤操作や Undo と競合しないように）。
  - 削除したリストでも、未購入の項目が残っている間は一覧に表示する（削除と同時に家族が項目を追加した場合や、削除後に Undo した場合に、項目が見えなくならないように）。項目がなくなると再び表示されなくなる。
  - リスト削除はオフラインでも行える。未購入の件数は端末にある情報で数える。
- リスト名の下に、「のこり N件 / M完了」のバッジだけを表示する（見出しや進捗バーは置かない）。
- 未購入の項目と、直近24時間にチェックした項目を、並び順に表示する。新しい項目は末尾に追加する。その上に「カードをタップして購入完了」と案内を表示する。
- 項目は1件ずつカードで表示し、カードの間を少し空ける。
- 各カードは、1行目に商品名と数量・単位（「2本」のような小さなバッジ）、2行目に備考を表示する（備考がなければ2行目は表示しない）。共有のリストにあるプライベートな項目には、鍵アイコンを付ける。
- 未購入の項目をタップするとチェックし、チェック済みの項目をタップするとチェックを外す。チェックボックスは表示しない。
- チェックした項目は別の場所に移さず、元の位置のまま、カードの背景を薄い色にし、商品名を打ち消し線と薄い文字で示す。2行目にはチェックの印と、チェックした人と時刻を表示する（例: 「✓ 花子 10:02」）。チェックから24時間が過ぎると表示しなくなる。
- **前回の買い物の片付け**: 買い終わったリスト（未購入が0件）に項目を追加すると、次の買い物が始まったとみなし、それまでのチェック済みの項目を表示しなくする（進捗にも数えない）。片付けは家族全員の画面に共通。購入の記録は残るので、予測には影響しない。買い物の途中（未購入が残っている）の追加では片付けない。片付けた項目は、リスト詳細からチェックを外せない（チェックの直後の Snackbar の「元に戻す」は使える）。
- 項目をチェックすると、他の家族の端末でもその項目が完了の表示になる。
- 行の右端にボタンを置く。未購入の項目は「編集」「削除」のアイコンボタン、チェック済みの項目は「元に戻す」ボタン（チェックを外す）と、自分がチェックした項目にだけ「削除」のアイコンボタン（購入の削除。§4.1）。スワイプでも同じ操作ができる。チェック済みの項目は、画面を移動したあとでもここからチェックを外せる。
- 項目はロングタップで持ち上げ、上下にドラッグして並べ替えられる（チェック済みの項目も含む）。並び順は家族で共有する。左右のスワイプとは指の向きで区別する。
- TalkBack では、項目のカスタムアクション「上へ移動」「下へ移動」で並べ替えられる。項目が1つもないときは「購入予定の商品はありません」と表示する。
- チェックの直後に、Undo できる Snackbar（約5秒）を表示する。
- チェックと Undo は家族の誰でも行える（プライベートな項目は本人だけが見えるので、本人だけが行える）。
- **スワイプ操作**: 「→ チェック、← 取り消し」で統一する。

  | 場所 | → スワイプ | ← スワイプ |
  |---|---|---|
  | 未購入の項目 | チェックする | 項目を削除する |
  | チェック済みの項目 | なし | チェックを外す |

  - 削除した直後は「元に戻す」付きの Snackbar を表示する。元に戻した項目は、削除する前の位置に戻る。
  - TalkBack では、項目をダブルタップするとチェックの切り替えになる。ほかの操作はボタンで行える。
- **項目の編集**
  - 未購入の項目の「編集」ボタンを押すと、商品詳細入力画面を編集モード（タイトル「商品の編集」、確定ボタン「更新する」）で開き、商品名・数量・単位・備考を変更できる。公開範囲は表示するだけで、変更できない。
  - 編集をやめると（✕ か戻るキー）、変更せずにリスト詳細に戻る。商品追加欄に入力途中の商品名があれば、そのまま残る。
  - チェック済みの項目は編集できない（購入の記録と内容を食い違わせないため）。編集したい場合は、チェックを外してから行う。
  - 編集中に他のメンバーがその項目をチェックまたは削除した場合は、変更を反映せず、その旨を表示する。
- **商品の追加**
  - 画面下部に商品追加欄（「商品名を入力して追加…」）を常に表示する。
  - 商品追加欄にフォーカスすると、サジェストのボトムシートが開く。シートの上部に商品名の入力欄があり、ソフトキーボードに追従する。背面のリスト詳細は半透明の幕で覆う。シートを閉じている間は、サジェストを表示しない。
  - シートを閉じると（戻るキーや幕のタップ）、入力途中の商品名は商品追加欄に残る。
  - 未入力のときは、購入時期が近い商品を提示する（§4.3）。入力中は、過去の商品名から補完候補を表示する（購入周期の条件は使わない）。候補は「履歴」「予測」などに分けず、1つの一覧で表示する。
  - 入力中は、候補の上に「数量を設定して追加」を表示する（商品名は含めない）。タップすると、入力した商品名で商品詳細入力画面に進む。
  - 候補の名前の部分をタップすると、その候補の内容（商品名、前回の数量・単位）を引き継いで、商品詳細入力画面に進む。
  - 候補の名前の部分を長押しすると、その商品（統合先）の商品名の管理の画面を開く（まとめる、非表示にする、購入履歴を見る、など）。戻るとシートを開き直し（入力した文字は残す）、候補はそのときの状態（まとめた・非表示にした結果）で作り直す。
  - 候補の右端の「＋」をタップすると、前回の数量・単位（なければ数量1・単位「個」）で、すぐにリストの末尾に追加する。
  - 商品名を入力して IME の Enter/Done を押すと、数量1・単位「個」・備考なしで、すぐにリストの末尾に追加する。シートは閉じず、入力欄を空にしてキーボードを開いたままにし、続けて次の商品を入力できる。
  - 「＋」と Enter による追加の公開範囲は、そのリストで直前に選んだ公開範囲を引き継ぐ（§3.4）。共有のリストでは、シートの入力欄の下に今の公開範囲（「全員に共有」「自分のみ」）を表示し、その場で切り替えられる。時間がたっても、どちらで追加されるかが分かるようにするため。プライベートのリストでは表示しない。
  - 未購入リストにすでにある商品の補完候補には、どのリストにあるかを添えて「追加済み（スーパー）」と表示する（複数なら「追加済み（スーパー・薬局）」。開いているリストを先にする）。追加はできる。
  - いつもより早い再購入の場合（§4.5）、その商品の補完候補に前回の購入日と普段の周期（周期が分からなければ前回の購入日だけ）を控えめに表示する。
- **商品詳細入力画面**
  - 上部に ✕（閉じる）と「商品の詳細入力」。その下に追加先（例: 「追加先: スーパー（共有リスト 3人）」）を表示する。
  - 商品名（編集できる）。購入の記録があれば、その下に前回の数量・購入日・普段の周期を表示する（例: 「前回: 1パック（10/18 購入・約14日ごと）」）。いつもより早い再購入の場合は、ここで知らせる（§4.5）。
  - 数量: 大きな数字と「−」「＋」のボタン。初期値は1。
  - 単位: 「個」「本」「パック」「袋」などの候補と自由入力。候補から来た場合は前回の単位、それ以外は「個」を初期値にする。単位は空欄でもよい。
  - 公開範囲: 共有のリストでは「全員に共有」「自分のみ」を選ぶ。初期値はそのリストで直前に選んだ公開範囲。「※ 登録後に公開範囲を変更することはできません」と注記する。プライベートのリストでは表示しない（すべてプライベートになる）。
  - 備考（任意・複数行）。過去にその商品に付けた備考を候補として表示する。
  - 入力した商品名が既存の商品と似ている場合（§4.2）、「『牛乳』と同じ商品として記録する」という選択肢を表示する。初期状態は未選択。
  - 最下部の「リストに追加する」で、リストの末尾に追加してリスト詳細に戻る。✕ か戻るキーで閉じると、追加せずにサジェストのシートに戻る（入力した商品名は残る）。
- **他のメンバーによるチェックの通知**（二重購入に気づくため）
  - 自分がチェックした項目を他のメンバーが先にチェックしていた場合、「牛乳は 花子さんが 10:02 にチェック済みです」と表示する。この場合、購入は1件だけ記録される。
  - リスト詳細を開いている間に、他のメンバーがこのリストの項目をチェックしたら、「花子さんが牛乳をチェックしました」と表示する。約3秒以内の複数のチェックは1件にまとめる（例: 「花子さんが牛乳ほか2件をチェックしました」）。
  - 画面を開いた時点ですでにチェック済みだった項目は通知しない。
  - 自分の Undo Snackbar と重なった場合は、Undo Snackbar を先に表示する。
  - オフラインの間は他のメンバーのチェックが届かないため、通知は接続が戻るまで遅れる。

### 3.3 オフライン時の振る舞い
- オフラインの間は、上部のバーの直下に「オフライン表示中（変更は再接続時に同期されます）」と表示する。表示中も、キャッシュ済みのリストの閲覧・操作は通常どおり行える。
- 次の操作を除き、すべての操作をオフラインでも行える（チェック、Undo、項目の追加・編集・削除、リストの作成・編集・削除、並べ替え、家族の作成、ログアウト、商品をまとめる・解除するなど）。オフラインで行った変更は、接続が戻ると家族に共有される。
- オフラインでできない操作と、その理由:
  - 家族への参加・ほかの家族への合流: 招待コードが有効かをサーバーで確かめる必要があるため。
  - 招待の発行: 招待された人がコードを入力するのに通信が必要で、オフラインで発行しても使えないため。
  - 招待の取り消し: 取り消しがサーバーに届くまでは、そのコードで参加できてしまい、取り消したつもりでも参加を防げないため。
  - メンバーの削除: 削除がサーバーに届くまでは、外したはずの人がリストを読み書きできてしまうため。
  - 家族からの離脱: オフラインで抜けても、その後の参加には通信が必要で利点がないうえ、オーナーの引き継ぎ先を古い情報で選ぶおそれがあるため。
  - アカウントの削除: Google での再ログインとアカウントの削除に通信が必要なため。
  - ログイン: Google でのログインに通信が必要なため。
- オフラインでできない操作をしようとした場合は、理由を表示する。
- オフラインでチェックした項目は、その場でチェック済みとして表示し、家族に共有されるまで「未同期」マークを付ける。アプリを閉じても失われず、接続が戻ると自動で共有される。
- オフライン中に追加した項目なども、共有されるまで「未同期」マークを付ける。
- 共有されないまま7日を過ぎたチェックや、共有の前に家族から外された場合など、反映できなかった変更は「牛乳のチェックを反映できませんでした」のように知らせる。

### 3.4 公開範囲
- **リスト**: 作成するときに「共有」か「プライベート」を選ぶ（初期値は共有）。作成したあとは変更できない。プライベートのリストは、作成した本人にだけ表示する。
- **商品（項目）**: 共有のリストでは、追加するときに「全員に共有」か「自分のみ」を選ぶ。登録したあとは変更できない。プライベートのリストの項目は、すべてプライベートになる。
- プライベートな項目は、登録した本人にだけ表示する。他のメンバーの画面では、件数・進捗・サジェスト・チェックの通知のいずれにも現れない。
- プライベートな項目の購入の記録も、本人にだけ見える。他のメンバーの周期の予測やサジェストには使わない。本人の予測には、共有とプライベートの両方の記録を使う。
- **直前の公開範囲の引き継ぎ**: 共有のリストでは、リストごとに直前に選んだ公開範囲を覚えておき、次の追加の初期値にする。
  - 初回の追加では「共有」を初期値にする。
  - 商品詳細入力画面で選んで追加すると、その公開範囲がそのリストの次回以降の初期値になる。
  - サジェストのシートで切り替えた場合も、その公開範囲がそのリストの次回以降の初期値になる（商品詳細入力画面の初期値にも使う）。
  - Enter による追加と、候補の「＋」による追加は、直前の公開範囲をそのまま使う（初期値を変えない）。
  - 覚えておくのはアプリを起動している間だけで、アプリを起動し直すと「共有」に戻る。
- 共有のリストにあるプライベートな項目には、鍵アイコンを付ける。プライベートのリストでは、項目ごとの鍵アイコンは付けない（すべてプライベートのため）。

### 3.5 家族共有・設定
- **ログイン**
  - ログインしていないときは、ログイン画面を表示する。Google アカウントでログインする。
  - ログインしていて家族に参加していないときは、「家族の作成・参加」画面を表示する。「家族と共有する」（家族を作成する）と「招待コードで参加する」を選べる。
- **家族の作成**: 作成した人がオーナーになる。家族の名前は入力しない（内部的に「○○さんの家族」とし、画面には表示しない）。作成したあとは家族画面を開き、招待を促す。
- **招待**
  - 家族のメンバーなら誰でも招待を発行でき、Android の共有シートで送る。文面には招待リンクと招待コードの両方を含める。
  - 招待コードは10文字（読み間違えやすい文字を含まない）で、24時間有効、1回だけ使える。1人に1つ発行する。発行したコードは、家族のメンバーが取り消せる。
  - アプリが入っている端末で招待リンクを開くと、アプリが起動して参加の確認画面を表示する。ログインしていない場合は、ログイン後にこの確認に戻る。
  - アプリが入っていない端末で招待リンクを開くと、ストアへの案内と招待コードを表示するページが開く。
  - アプリ内で招待コードを入力しても参加できる。
- **参加の確認**
  - 招待リンクから開いた場合も、招待コードを入力した場合も、「○○さんの家族に参加しますか？」（○○は招待を発行した人の名前）と確認する。承認するまで参加しない。
  - コードが使えない場合は理由を表示する: 「招待コードが見つかりません」（存在しない・取り消された）、「招待コードの有効期限が切れています」、「この招待コードはすでに使われています」。
  - ほかのメンバーがいる家族に参加している人が招待リンクを開いた場合は、参加せず「すでに家族に参加しています。別の家族に参加するには、今の家族から抜けてください」と表示する。
  - 自分しかいない家族に参加している人が招待リンクを開いた場合は、合流の確認を表示する（下記「ほかの家族への合流」）。
- **家族画面**: リスト一覧の上部バーのアバターから開く。次のものを表示する。
  - 自分のアカウント（アバター、名前、メールアドレス）と「表示名を変更」。
  - 家族のメンバー一覧（アバター、名前、オーナーかどうか）と、ほかのメンバーごとの「呼び名を設定」。
  - 「招待する」ボタンと、発行済みで有効な招待コードの一覧（有効期限と「取り消す」）。
  - 「商品名の管理」（商品名の管理の画面を開く）。
  - 「家族から抜ける」「ログアウト」「アカウントを削除」。
  - 家族に自分しかいないときは、メンバー一覧の代わりに「ほかの家族グループに参加する」（招待コードの入力へ進む）を表示し、「家族から抜ける」は表示しない。
- **表示名と呼び名**
  - 自分の表示名: 各ユーザーは、CartMate の中での自分の表示名を設定・変更・解除できる。家族全員に対する基本の表示名になる。
  - 呼び名: 各ユーザーは、ほかのメンバーごとに自分だけの呼び名（「ママ」「お母さん」など）を設定・変更・解除できる。呼び名は設定した本人の画面だけに出し、ほかのメンバーの表示には影響しない。
  - 表示の優先順位: ①自分がその人に付けた呼び名 ②その人の表示名 ③その人の Google アカウントの名前。Google アカウントの名前は変更しない。
  - 表示名と呼び名は20文字まで。前後の空白は除き、空にすると解除になる。
  - チェックした人の名前、ほかのメンバーのチェックの通知、家族画面など、メンバーの名前を出すところすべてに使う。招待の確認画面の「○○さんの家族」には、招待した人の表示名（なければ Google アカウントの名前）を出す（参加する前なので、呼び名はない）。
  - 家族画面では、呼び名や表示名が Google アカウントの名前と違うとき、2行目に Google アカウントの名前を出して、誰か分かるようにする。
  - 抜けたメンバーでも、呼び名を付けていればその呼び名を出す。付けていなければ「退会したメンバー」と出す。
  - 自分の表示名は、ほかの家族への合流や、抜けたあとの参加でも引き継ぐ。呼び名は家族を移っても残る。どちらもオフラインで設定できる。
- **メンバーの削除**: オーナーは、自分以外のメンバーを家族から削除できる。削除されたメンバーの端末は「家族の作成・参加」画面に戻り、「共有が取り消されました」と表示する。
- **家族からの離脱**
  - 確認ダイアログを経て、家族から抜ける。抜けたあとは「家族の作成・参加」画面に戻る。
  - 自分のプライベートなリストと項目は、元の家族の中に残り、誰からも見えなくなる。同じ家族にもう一度参加すると、再び見える。確認ダイアログでこのことを伝える。
  - オーナーが抜けると、残りのメンバーのうち参加がいちばん早い人がオーナーを引き継ぐ。引き継ぐ相手は選べない。
  - 最後のメンバーが抜けても、家族のデータは削除しない（誰からもアクセスできなくなる）。
- **ほかの家族への合流**: 家族を作ったあとで、別の家族がすでにあると分かった場合に、その家族へ移るための機能。
  - 家族に自分しかいないときだけ行える。家族画面の「ほかの家族グループに参加する」から招待コードを入力するか、招待リンクを開く。
  - 確認画面では「○○さんの家族に参加しますか？」に加えて、「あなたのリスト（N件）は○○さんの家族に移ります」と伝える。ボタンは「合流する」。
  - 自分のリスト・項目・商品・購入の記録を、合流先の家族に移す。プライベートなものは、移ったあともプライベートのまま。
  - 移したリストは、合流先のリストの末尾に、元の並び順のまま加える。同じ名前のリストがあっても、1つにまとめない（公開範囲が違う場合や、別の店だった場合に戻せないため）。不要なら合流後に削除する。
  - 同じ商品名の商品は、同じ商品として扱う（§4.2）。
  - 移している間は進み具合を表示する。途中で中断しても、もう一度合流を行うと続きから移す。
  - 合流したあと、元の家族は誰もいない状態で残る（削除しない）。
- **ログアウト**: ログイン画面に戻る。データは削除しない。
- **アカウントの削除**
  - 確認ダイアログを経て、Google での再ログインを求めてから削除する。
  - 自分のプライベートなリスト・項目・購入の記録と、アカウントの情報を削除し、家族から抜ける（オーナーの引き継ぎは離脱と同じ）。
  - 共有のリスト・項目・購入の記録は、家族のデータとして残す。作った人やチェックした人は「退会したメンバー」と表示する。
  - アプリの外からも削除を依頼できるよう、削除の方法を案内する Web ページを用意する。
- 家族から抜けた・外されたメンバーが作った共有のデータも、作った人を「退会したメンバー」と表示する。
- **アバター**: Google アカウントの写真を使う。写真がない場合は、名前の頭文字を表示する。
- **商品名の管理**: 同じ商品の別表記をまとめる（統合する）。まとめると、購入履歴を合わせて周期を計算する。
  - 一覧には、どこにもまとめていない商品（統合先）を並べ、まとめている件数と、辞書の名寄せを分けて表示する。辞書の名寄せは、同じ品目としてまとめている名前を出す（辞書の名前と同じ名前の商品が1つだけなら出さない）。
  - 一覧は検索欄で絞り込める。商品名か、まとめている商品の名前に、入力した文字が含まれる商品を出す（カタカナとひらがな、全角と半角、大文字と小文字は区別しない。漢字と読みは結び付けない）。非表示の商品も同じく絞り込む。
  - 統合先の商品を開くと、そこにまとめている商品（多段の統合もたどる）と件数を表示し、1件ずつ「解除」できる。「商品をまとめる」から、まとめる商品を追加したり外したりできる。商品の画面には、前回の購入日と、周期が分かればその周期（「前回: 10/18 購入（約14日ごと）」）を表示する。
  - 「商品をまとめる」では、統合先を固定して表示し、まとめる商品をチェックボックスで複数選ぶ。今まとめている商品はチェックした状態で並び、チェックを外すとその商品の統合を解除する。「すべて解除」で、今まとめている商品も含めてチェックをすべて外せる。候補は検索欄で絞り込める（絞り込んでも選択は残る）。チェックしている件数を表示し、確認のあと一度に反映する。件数に上限はない。統合先そのものと、ほかの商品にまとめられている商品は候補に出ない。ほかの商品をまとめている商品を選ぶと、その下の商品も一緒に同じ統合先へ移る（確認で伝える）。外した商品にまとまっていた商品は、統合先に残る。反映を送ると統合先の画面に戻る。
  - まとめられている商品を開くと、今の統合先を表示し、「解除」できる。統合先を変えるときは、解除してから新しい統合先でまとめる（統合先を直接変える操作はない）。
  - 解除すると、その商品だけが外れる。その商品にまとまっていた商品は、元の統合先に残る。
  - まとめる・解除するはオフラインでもでき、家族で共有する。ほかのメンバーが先に統合関係を変えていて反映できなかった場合は、何も反映せずに（一部だけ反映することはない。ただし「商品をまとめる」で一度に多くの商品を変えて書き込みを分けて送った場合は、反映できた分だけが残る）、画面を最新の状態に戻し、「商品のまとめ方を変更できませんでした」と知らせる。アプリを閉じている間に反映できなかったと分かった場合は、次に開いたときに知らせる。
  - 辞書でまとめられた商品は、統合先の画面で「別の商品として扱う」を選べる（外した商品は「辞書でまとめる」で戻せる）。
  - **名前の訂正**: 打ち間違えた名前のまま完了した場合に、統合先の画面の「商品名を変更する」で正しい名前を入力して直せる。購入の記録とそこに残した名前は書き換えず、正しい名前の商品にまとめる（その商品がまだなければ作る）。1件目の記録でも直せる。訂正した商品にまとまっていた商品も一緒に移る。訂正したあとは、正しい名前の商品の画面に移り、元の名前は「まとめている商品」に出る（解除すれば元に戻る）。正しい名前の商品が非表示なら、また表示する。
  - **一時的に非表示**: 試しに入れた名前など、使わない商品を、統合先の画面のサジェストへの出し方で「一時的に非表示」にできる（§4.3）。家族で共有し、オフラインでもできる。
    - 非表示にした商品（まとめている商品を含む）は、商品名の管理の一覧、入力中の補完、時期が近い商品の提案、表記ゆれの候補に出さず、予測にも使わない。購入の記録とリストの項目は消さない（今リストにある項目もそのまま表示する）。
    - 商品名の管理の一番下の「非表示の商品（N件）」に並べ、開くと通常の商品と同じ画面で、「通常どおり表示」を選んで戻せる。戻すと、非表示にする前の記録も、また予測に使う。
    - 非表示にしたあとに、その商品（まとめている商品を含む）の項目が追加されるか購入されると、自動でまた表示する（同じ名前をまた入力した場合）。このとき、非表示にする前の購入の記録は予測に使わない（試しの記録が周期に混ざらないように）。判定は自分に見える項目と購入の記録で行う。
    - 統合されている商品は非表示にできない（統合先を非表示にする）。非表示の商品は「商品をまとめる」の候補に出さない。
- サジェストの閾値などの設定項目は設けない。

## 4. 購入履歴・予測

### 4.1 購入の記録
- 購入日は、端末でチェックした日とする（オフラインでチェックして後から共有された場合も、チェックした日）。商品を登録した日時とは区別する。
- 購入の記録には、商品、購入時の商品名、数量・単位・備考、公開範囲、購入時のリスト名、チェックした日時とチェックした人、元の買い物項目を残す。
- リストを削除しても購入の記録は残る。
- **購入の削除**: 自分がチェックした購入は、チェック済みの項目と購入の記録をまとめて削除できる（サプライズのプレゼントを共有のまま買ってしまった、間違えて記録した、など）。
  - 入口は、リスト詳細のチェック済みの項目（自分がチェックしたものだけ）と、商品ごとの購入履歴の記録（自分がチェックしたものだけ）。確認ダイアログで「家族の画面からも消え、元に戻せない」ことを伝える。
  - 商品名の管理の商品の画面からは、その商品（まとめている商品と辞書でまとまる商品を含む）の自分の購入を、「自分の購入をすべて削除（N件）」でまとめて削除できる。確認ダイアログで件数と、ほかのメンバーの購入が残る場合はその件数を伝える。
  - 購入の記録がすべてなくなった商品は、商品名の管理から外れる。商品の画面や購入履歴の画面を開いていた場合は、商品名の管理に戻り（サジェストの長押しから開いた場合は、開く前のリスト詳細に戻る）、外れたことを知らせる。
  - 項目を作った人は問わない（ほかのメンバーが追加した項目を、自分がサプライズとして買った場合も消せる）。ほかのメンバーがチェックした購入は削除できない。
  - 家族の画面からも消える（オフラインの端末は、つながったときに消える）。ほかのメンバーの画面に出た「チェックしました」の通知は取り消せない。商品名は商品のデータに残るが、ほかに記録がなければ画面には出ない。
  - 削除した購入の項目のチェックを、ほかのメンバーが外そうとした場合は、「すでにチェックが外されています」と表示する。
  - 削除と比べて、記録を残したまま家族からだけ隠す（自分のみにする）方式は、ほかのメンバーが作った項目を扱えず、1回限りの買い物では記録を残す意味が小さいので採らない。自分用に繰り返し買う物の周期を残したい場合に必要になれば、あとで検討する。
- Undo すると購入の記録は無効になり、予測に使われなくなる。
- 同じ項目を複数の端末が同時にチェックしても、購入は1件しか記録されない。
- 同じ項目を Undo してから再びチェックした場合、購入は1件として記録し直す。
- 非表示にした商品の購入の記録は予測に使わない。また表示された商品でも、非表示にする前の記録は使わない（「表示する」で戻した場合は使う。§3.5）。
- **商品ごとの購入履歴**: 商品名の管理の商品の画面の「購入履歴」から、その商品（まとめている商品と、辞書でまとまる商品を含む）の直近365日の購入の記録を新しい順に見られる。購入日、記録に残した商品名、数量・単位、リスト名、チェックした人を表示する。Undo した記録は出さない。
- **予測に使わない**: 商品ごとの購入履歴から、個々の購入の記録を「予測に使わない」にできる（間違えてチェックした、たまたま1回だけ買った、など）。記録は消さずに残し、いつでも元に戻せる。サジェストの補正として、名寄せの訂正（§4.2）と同じく家族で共有し、自動の判定より優先する。共有の記録は家族の誰でも、プライベートの記録は本人だけが切り替えられる。

### 4.2 商品の同一性
- 次の差だけの商品名は、同じ商品として記録する: Unicode 正規化（全角・半角を含む）、前後の空白、連続した空白、英字の大文字・小文字。
- **名寄せ辞書**: アプリに同梱した辞書に載っている表記ゆれ（「卵」と「たまご」、「ごま油」と「胡麻油」など）は、読み取るとき（予測・サジェスト・補完・購入の記録の集計）に同じ商品として扱う。入力した商品名と、記録された商品はそのまま残し、書き換えない。
  - 辞書の目的は、購入履歴に登録された商品の名寄せ。辞書に載っているだけで、まだ買っていない商品を提案や補完の候補にすることはしない（候補は購入履歴から作る）。
  - 辞書は端末の中だけで使い、照合のたびに外部のサービスへ問い合わせない。辞書はアプリの更新で更新する。
  - 「お茶」のように、ふつうは緑茶を指すが確定ではない言葉は、既定の同義語として扱い、商品名や備考の指定（「麦茶」など）を優先する。
  - 予測とサジェストでは、購入の記録ごとに、商品名に加えて備考からも、名寄せに関係する属性（品目、形態、容量、用途、詰め替えなどの種類）を読み取って判定する。
    - 品目: 「お茶」のような既定の同義語は、商品名や備考に品目の語（「麦茶」）があればその品目、なければ既定の品目（緑茶）として数える。商品名と備考の品目が食い違う場合（「緑茶」＋備考「麦茶」）は、どちらにもまとめない。
    - 形態・容量・用途・種類: 属性が違う記録は別の商品として周期を数える。属性が未指定の記録と、属性が指定された記録も別に数える（未指定を一致とみなさない）。容量は書き方が違っても同じ量なら同じとみなす（「2L」「2リットル」「2000ml」）。「特売なら」「いつもの」のような判定に使わない語は無視する。
    - 時期が近い商品で、同じ名前が属性で分かれる場合は「緑茶（茶葉）」のように属性を添えて出し、「＋」では前回の備考も一緒に入れる。
    - 商品名の管理の辞書の名寄せと、表記ゆれの候補は、これまでどおり商品名だけで判定し、既定の同義語ではまとめない。
  - 辞書での名寄せが誤っている場合は、その商品について「別の商品として扱う」を選べる（商品名の管理の画面）。選んだ結果は家族で共有し、辞書を更新しても元に戻らない。
  - 辞書には「同じ商品」とは別に「購入周期だけ合わせて数える」関係（食パン6枚切りと8枚切りなど）と、「同じ商品にしない」組み合わせがある。周期だけの関係は、購入周期の計算だけで合算し、補完の候補や「追加済み」の判定では別の商品として扱う。
- それ以外の似た名前（「牛乳」と「牛乳 1L」、「ミルク」と「みるく」など）は候補として示すだけで、自動ではまとめない。ユーザーは、商品詳細入力画面の選択肢（§3.2）か商品名の管理（§3.5）でまとめられる。
- 辞書になく、読みや言い換えでしか結び付かない名前は、AI の判定で候補として示す（下記）。まとめるかはユーザーが選ぶ。候補にならない場合は、商品名の管理でまとめる。
- **AI による名寄せの候補**（フェーズ6）: 辞書と規則で決まらない名前を、外部の AI に判定させ、購入履歴の名寄せの精度を補う。
  - AI の役割は、購入履歴の名寄せの補助だけ。商品のカタログ作り、まだ買っていない商品の提案、入力の予測変換・補完には使わない。
  - AI には、商品名と、備考から規則で読み取った属性だけを送り、品目・形態・容量・用途・種類を答えさせる。2つの名前が同じかを直接決めさせることはしない。同じ商品の候補にするかは、端末の規則で判定する（品目が同じで、属性に矛盾がなく、統合禁止に当たらず、信頼度が十分なとき）。
  - **AI の判定では自動でまとめず、候補を出すだけにする。** 表記ゆれの候補（商品詳細入力画面）と商品名の管理に「AI の候補」として理由とともに出し、ユーザーが選んだものだけをまとめる。
  - AI に問い合わせるのは、共有の項目で初めて購入された商品で、手動の統合・分離がなく、辞書で品目が決まらず、選択肢を含む名前でなく、同じ名前と属性の判定がまだないときだけ。入力中や、リストに追加しただけでは問い合わせない。プライベートな項目だけで使った名前は送らない。uid・家族・リスト名・日時・数量も送らない。
  - 判定は家族で共有して保存し、同じ名前と属性では繰り返し問い合わせない。判定の理由を残し、なぜ候補になったかを商品名の管理で確かめられる。
  - 判定は非同期で行い、追加やチェックの操作を止めない。通信できない、上限に達した、応答が正しくない場合は、候補を出さず、辞書と購入履歴だけで使える。
  - 費用: AI の利用は全体で月1ドルを上限とし、超えたらその月は問い合わせない。家族ごとにも月の上限（100回）を設ける。AI の利用は設定1つで止められる。Firebase 側は無料枠に収め、少しでも課金されたら予算アラートで知らせる。
- **選択肢を含む商品名**（「カブもしくは大根」「カブか大根」など）は、どちらを買ったかが確定しないので、独立した商品として扱う。表記ゆれの候補を出さず、ほかの商品の候補にもならない。購入の記録も、その商品の周期としてだけ数える（カブ・大根の履歴には加えない）。選択の語は「もしくは」「または」「あるいは」「どちらか」「どっちか」「いずれか」「/」「or」と、前後がひらがな以外の「か」。AI の判定（下記）にも問い合わせない。
- 名寄せの優先順位は、ユーザーの手動の統合・分離 ＞ 統合禁止 ＞ 辞書 ＞ 機械的な正規化。AI の判定は候補を出すだけなので、これらを覆さない。
- 予測では、まとめた商品の購入記録を合算する。入力した商品名もそのまま残す。

### 4.3 購入周期と時期が近い商品の提案
- 同じ日の複数回の購入は、1回として数える。
- 購入した日が3日未満の商品は、周期を予測しない。
- 購入日を時系列に並べて隣り合う間隔を求め、直近最大10個の間隔の中央値を推定周期とする。
- 経過率 = 最後に購入してからの日数 / 推定周期。
- 未入力でフォーカスしたときは、周期が安定していて、経過率が80%以上300%以下の商品を、最大10件提示する。300%を超えた商品は、買うのをやめたとみなして提示しない。
  - 周期が安定しているとは、購入間隔のばらつき（中央絶対偏差 / 中央値）が0.5以下のこと。献立に合わせて買う食材のように、たまたまの間隔でばらつく商品は、補充が必要とはみなさず提示しない。周期を計算できることと、購入を勧めるべきことを区別する。食品のカテゴリでは判定しない（間隔が安定していれば、献立に使う食品でも提示する）。
  - 並び順: 経過率150%までは経過率の高い順。150%を超えた商品は、超えた分だけ順位を下げる（予定日を大きく過ぎた商品が、今ちょうど必要な商品より上に並ばないように）。同じなら、そのリストでの関連の強い順。
- 各候補には「約14日ごと・最後は16日前」のような補足を表示する。
- 家族のいずれかの未購入リストにすでにある商品は提示しない。
- 予測は参考情報であり、商品を自動でリストに追加することはしない。
- **サジェストへの出し方**: 商品ごと（統合先）に、商品名の管理の商品の画面で次から選べる。全リスト共通で、家族で共有し、オフラインでもできる。
  - 通常どおり表示: 購入の周期に合わせて候補に出す。
  - 一時的に非表示: 一覧・補完・時期が近い商品・表記ゆれの候補に出さず、予測にも使わない。再購入すると候補に戻る（§3.5）。
  - 常に非表示: 時期が近い商品・入力中の補完・表記ゆれの候補・早すぎる再購入の注意に出さない。再購入しても、購入の完了や周期の計算でも解除されない。商品の追加・購入と購入履歴の記録は今までどおりで、商品詳細入力画面の「前回: …」も出す。商品名の管理の「非表示の商品」に、一時的に非表示と分けて出し、設定した人を表示する。そこから解除できる。
  - 一時的に非表示と常に非表示は、どちらか一方になる。
  - 名前の訂正や、購入の記録の「予測に使わない」では、この設定を変えない。名前の訂正で正しい名前の商品を新しく作るときは、設定を引き継ぐ。既にある商品にまとめる場合（名前の訂正・商品をまとめる）は、統合先の設定になり、設定が変わるときは確認の画面で伝える。統合を解除すると、まとめていた商品の設定がまた効く。
- 予測には直近365日の購入記録を使う。そのため、周期がおよそ180日を超える商品は予測されない。

### 4.4 リスト名と商品の関連
- 購入の記録に、購入時のリスト名を残す。リスト名を変更しても、記録に残したリスト名は書き換えない。そのため、名前を変えた直後は、そのリストで提示する候補が少なくなることがある。
- 同じ名前の過去のリストで買った商品を、優先して候補にする。
- 名前が違うリストでも（「スーパー」と「イオン」など）、過去に買った商品の重なりが大きければ関連するリストとみなし、そのリストで買った商品も候補にする。どちらかのリストの購入商品が少なく判定できない場合は、関連付けない。
- **周期の計算**には、リストに関係なく家族全体の購入記録（自分に見えるもの。§3.4）を使う。**そのリストで提示する候補の選択**にだけ、リストの関連を使う。
- 同じ名前のリストの履歴も、関連するリストもない場合（新しい名前のリストなど）は、時期が近い商品を提示せず、「商品名を入力すると候補が出ます」とだけ表示する。

### 4.5 早すぎる再購入の注意
- 経過率が50%未満の商品は、サジェストの補完候補と商品詳細入力画面で、前回の購入日と普段の周期を控えめに表示する（例: 「前回 10/18 に購入・いつもは約14日ごと」）。
- Enter で候補を選ばずに追加した場合は、注意を表示しない（連続入力を止めないため）。
- 注意は表示するだけで、追加を妨げない。
- 購入した日が3日未満の商品や、購入間隔のばらつきが大きく周期が不安定な商品は、経過率で判定できない。これらの商品は、前回の購入から3日以内のときだけ、前回の購入日を控えめに表示する（例: 「前回 10/28 に購入」。商品詳細入力画面では「最近購入したばかりです」）。家族がもう買ってきたのに気づかず、また追加するのを防ぐため。

## 5. データの扱い
- 家族ごとのデータは、その家族のメンバーだけが読み書きできる。プライベートなリスト・項目・購入の記録は、登録した本人だけが読み書きできる。
- 家族グループと商品は削除しない。購入の記録は、自分がチェックした購入だけを項目ごと削除できる（§4.1）。リストは削除しても、購入の記録から参照できるよう内部的には残す。ただし、アカウントを削除したときは、本人のプライベートなリスト・項目・購入の記録を削除する（§3.5）。予測に使いたくない購入の記録は、削除ではなく「予測に使わない」にする（§4.1）。使わない商品は、削除ではなく非表示にする（§3.5）。
- 項目の物理的な削除は、未購入の項目に限る。

データ構造の詳細は [design/data-model.md](design/data-model.md) を参照。

## 6. リアルタイム同期・競合
- 家族のリストと項目の変更は、オンラインの端末にリアルタイムに反映される。
- チェックと購入の記録は、1つの操作として同時に成立する。片方だけが反映された状態にはならない。
- 複数の端末が同時に操作した場合の結果は次のとおり。

  | 状況 | 結果 |
  |---|---|
  | 2人が同じ項目を同時にチェック | 先にチェックした人のチェックが残り、もう一方には先にチェックした人と時刻を表示する |
  | 他のメンバーがすでに Undo した項目を Undo | 「すでにチェックが外されています」と表示する |
  | チェックと削除が同時 | 先に行われた方が有効になる。チェック済みの項目は削除されない |
  | リスト削除と項目追加が同時 | 項目は失われず、リストは一覧に表示されたままになる |
  | 使用回数1の招待コードで2人が同時に参加 | 1人だけが参加できる |

## 7. 非機能要件
- Android 端末で片手で操作しやすい UI、IME 操作、アクセシビリティ、読みやすい文字サイズ（文字サイズ200%でも操作できる）。
- 見た目は淡いライラック（`#FFF7FF`）を背景にし、ブランドカラーはライラックパープル（`#6B4E8C`）とする。完了やチェックの表示を含め、緑は使わない。端末がダークモードでも明るい配色のまま表示する。配色・文字・余白・角丸の値は [design-tokens.md](design-tokens.md) に従う。
- 起動・リスト表示・チェック操作が軽快であること。
- 家族グループの外からはアクセスできない。招待コードは十分な乱数・期限・使用回数の制限を設ける。改造したクライアントからのアクセスを抑えるため、Firebase App Check を使う。
- Firestore の読み取り数が増えすぎないよう、購読の範囲と履歴の取得件数を限定する。
- サジェストの計算と購入周期の予測は、端末上で Kotlin で行う。外部の AI API は、名寄せの候補の判定（§4.2）にだけ、Cloud Functions を通して使う。アプリに API キーを入れない。

## 8. MVP の対象外
GPS による自動切り替え、独立したサジェスト画面、バーコード、レシート OCR、価格比較、予算管理、プッシュ通知（アプリ内の通知は §3.2 のとおり行う）、表記ゆれの完全自動統合、購入場所マスタ、Google ファミリーグループとの自動連携、常時動く専用サーバーの運用、「カゴに入れた」状態や担当者の割り当てによる二重購入の事前防止、チェック済みの項目の編集、登録後の公開範囲の変更、サジェスト閾値の設定、家族名の変更、複数の家族グループへの参加、引き継ぐ相手を選んでのオーナーの譲渡。

## 10. 受け入れ条件
- 家族2人が、別々の Google アカウントで同じ家族グループに参加できる（招待リンクと招待コードのどちらでも）。
- 家族から抜けた人と、オーナーに外された人は、「家族の作成・参加」画面に戻る。オーナーが抜けると、残りのメンバーのうち参加がいちばん早い人がオーナーになる。
- アカウントを削除すると、本人のプライベートなデータが削除され、共有のデータは家族の端末に残る。
- 自分しかいない家族からほかの家族に合流すると、自分のリストと購入の記録が合流先に移り、合流先で予測に使われる。
- 一方が追加・チェック・Undo・削除した内容が、オンラインのもう一方の端末に速やかに反映される。
- 「スーパー」「薬局」など任意の名前のリストを作成でき、各リストにはそのリストの商品だけが表示される。リスト名と備考はあとから変更できる。
- 商品名で Enter を押すとすぐに登録され（数量1・単位「個」）、シートを開いたまま連続して追加できる。
- 「数量を設定して追加」または候補の名前のタップから商品詳細入力画面に進み、数量・単位・公開範囲・備考を指定して登録できる。
- 商品追加欄にフォーカスしてサジェストのシートを開くまでは、サジェストが表示されない。
- 同じ商品を買った日が2日までは周期のサジェストを出さず、3日目以降に予測を始める。
- 同じ商品の別表記をユーザーが紐付けられ、統合した購入記録で周期を計算できる。
- 同じ名前のリストと、商品の傾向が似た別名のリストの購入記録を、候補の選択に活用できる。
- いつもより早い再購入のときに注意が出て、利用者はそのまま登録できる。
- リストを削除しても、購入記録と予測に必要な情報が残る。
- 同時にチェックしても購入記録が重複せず、Undo すると予測から除外される。
- 2人が同じ項目をチェックすると、後からチェックした人に、先にチェックした人と時刻が表示される。
- オフラインでチェックした項目が、アプリを閉じても失われず、接続が戻ると家族の端末に反映される。購入日はチェックした日になる。
- 未購入の項目を ← スワイプで削除でき、「元に戻す」で復元できる。
- リストと項目をロングタップからのドラッグで並べ替えられ、並び順がもう一方の端末にも反映される。
- 未購入の項目の「編集」ボタンから、商品名・数量・単位・備考を変更できる。
- 項目のタップでチェックを切り替えられる。
- プライベートなリストと、共有のリストに追加したプライベートな項目は、もう一方の端末に表示されない。その購入記録は、もう一方の予測とサジェストに使われない。
- 共有のリストで「自分のみ」を選んで追加すると、そのリストでの次の Enter・「＋」による追加もプライベートになる。
