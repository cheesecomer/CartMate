# Stitch への指示文: 家族とアカウントの画面の最終稿

Stitch のたたき台を最終稿に仕上げるための指示文です。4つに分けて、手順1から順に1つずつ Stitch に貼ります。手順1〜3では画面だけを作り直させ、すべての画面がそろってから、手順4で仕様書を書き出させます（1回で画面と文書の両方を頼むと、文書だけが書き出されるため）。各手順の「ここから」〜「ここまで」の間を貼ってください。

画面がそろったら、Stitch の書き出し機能で画面（画像と HTML）を書き出します。

## 手順1: 共通の値と、ログイン・家族の作成・リスト一覧

家族とアカウントの画面を、実装に渡す最終稿に仕上げます。何回かに分けて頼みます。今回は次の4画面です。画面をキャンバス上で作り直してください（たたき台の画面を更新するか、新しい画面として生成する）。この段階では、ドキュメントやマークダウンは書かないでください。検討用の別案、デバッグ用の切り替えボタン、説明用の注記は画面から取り除き、採用する1案だけにします。

- 文字（日本語は端末の標準の書体。英字だけの装飾的な書体は使わない）

- 文字サイズ 200% で崩れない。タップ領域は 48dp 以上。
- 写真がないアバターは、名前の頭文字を `#F2E7FE` の円に表示する。
- 家族名は表示しない。家族のアイコンや写真もない。
- 指示にないボタンや情報（家族名の編集、オーナーの譲渡、設定、ヘルプ、QRコードなど）は入れない。

■ すべての画面に共通して直すこと

- カードに影を付けない（1dp の枠線 `#CAC4CF` だけ）。

## 手順2: 招待コードと参加の確認

ここから

続けて、次の5画面を最終稿に仕上げてください。画面をキャンバス上で作り直してください（たたき台の画面を更新するか、新しい画面として生成する）。この段階では、ドキュメントやマークダウンは書かないでください。「デザインの値」と「すべての画面に共通して直すこと」は、前回と同じものを守ります。

| 画面名 | 内容 |
|---|---|
| `join_code_entry` | 招待コードの入力 |
| `join_code_entry_error` | 招待コードの入力（「招待コードが見つかりません」） |
| `join_confirm` | 参加の確認（「花子さんの家族に参加しますか？」） |
| `join_confirm_expired` | 参加の確認（「招待コードの有効期限が切れています」、「閉じる」だけ） |
| `join_confirm_merge` | 参加の確認（自分しかいない家族から、ほかの家族に合流する場合） |

■ 画面ごとに直すこと

`join_code_entry`
- 上部バーは「← 招待コードで参加」。
- 10個の入力枠が画面からはみ出している。1つの入力欄に「7KQ2-M9XP-HA」の形（4・4・2文字の区切り。区切りは自動で入る）で表示する方式にして、画面幅に収める。英大文字と数字だけ。
- 「次へ」は10文字そろうまで押せない。
- 「家族の共有リストに参加 / 入力完了後、共有買い物リストが自動で同期されます」の案内カードは取り除く。

`join_code_entry_error`
- `join_code_entry` と同じ構成で、入力欄の枠と下のエラー文「招待コードが見つかりません」だけを赤にする。入力したコードの文字や鍵アイコンは赤にしない。
- 「QRコードで読み取る」は取り除く。
- 「有効期限（48時間）」「大文字・小文字の誤り」の説明は誤り（有効期限は24時間、大文字・小文字は区別しない）。補足を残すなら「コードが正しいか確認するか、家族に新しいコードを発行してもらってください」にする。
- 大きなエラーのアイコンは置かない。

`join_confirm`
- ダイアログ。招待した人のアバター、「花子さんの家族に参加しますか？」、1行の説明、「参加する」「キャンセル」だけにする。
- 「山田家グループ」のバッジは取り除く（家族名は表示しない）。
- 「買い物かごの即時同期」「買い忘れ防止の通知共有」の一覧は取り除く（プッシュ通知は機能にない）。
- 上部の人型アイコンは取り除く（アバターと重複する）。

`join_confirm_expired`
- 説明文の「家族のオーナーに発行してもらってください」は「家族に新しいコードを発行してもらってください」にする（招待はメンバーの誰でも発行できる）。
- カードの外の「困ったときはオーナーに直接再発行をご依頼ください」は取り除く。

`join_confirm_merge`
- `join_confirm` と同じ構成で、説明を「あなたのリスト（3件）は花子さんの家族に移ります。プライベートなリストは、合流後もあなただけに表示されます。」にする。
- ボタンは「合流する」と「キャンセル」。

## 手順3: 家族画面とダイアログ

ここから

続けて、次の4画面を最終稿に仕上げてください。画面をキャンバス上で作り直してください（たたき台の画面を更新するか、新しい画面として生成する）。この段階では、ドキュメントやマークダウンは書かないでください。「デザインの値」と「すべての画面に共通して直すこと」は、前回と同じものを守ります。

| 画面名 | 内容 |
|---|---|
| `family` | 家族（オーナーが見ている状態。ほかのメンバーがいる） |
| `family_solo` | 家族（まだ自分しかいない状態。ほかの家族に合流できる） |
| `family_leave_dialog` | 家族画面の上に「家族から抜けますか？」の確認ダイアログ |
| `family_delete_account_dialog` | 家族画面の上に「アカウントを削除しますか？」の確認ダイアログ |

■ 画面ごとに直すこと

`family`
- オーナーが見ている案（メンバー一覧があり、ほかのメンバーに「削除」があるもの）を採用する。
- 上部バーは「← 家族」。
- 構成は上から「自分のアカウント（アバター・名前・メールアドレス）」「メンバー一覧（オーナーに「オーナー」のラベル、自分の行に「（自分）」、ほかのメンバーの行に「削除」）」「招待する」と有効な招待コードの一覧（コード・「あと 23 時間で期限切れ」・「取り消す」）、最下部に区切って「家族から抜ける」「ログアウト」「アカウントを削除」。
- 「買い物リストの共有グループ」「3人参加中」の行と、「オーナー権限」のラベル、オーナーの盾アイコンは取り除く。
- 自分のアカウントの「あなた」バッジは取り除く（メンバー一覧の「（自分）」で足りる）。
- 招待コードの「コピー」ボタンは取り除く（コードは「招待する」の共有シートで文面ごと送る）。
- サンプル: 自分は山田 太郎（taro.yamada@gmail.com、オーナー、写真なし → 頭文字「山」）。メンバーは山田 花子（写真あり）、山田 健太（写真なし → 頭文字「健」）。招待コードは 7KQ2-M9XP-HA。

`family_solo`
- 「ほかの家族グループに参加する」「招待コードを入力する」がある案を採用する。まだ自分しかいない家族で、すでに別の家族がある場合に合流するための画面。
- 上部バー、「あなた」バッジ、招待コードの「コピー」は `family` と同じように直す。「買い物リストの共有グループ」「1人参加中」の行と緑の点、「合流・参加」のバッジは取り除く。
- 合流の説明は「家族から招待コードを受け取っている場合は、その家族に合流できます。あなたのリストは合流先の家族に移ります。」にする。
- 「家族から抜ける」は置かない（自分しかいないため）。最下部は「ログアウト」「アカウントを削除」。

`family_leave_dialog`
- ダイアログの背面は `family` の画面にする（今は別の画面になっている）。
- 見出し「家族から抜けますか？」、本文「あなたのプライベートなリストは見られなくなります。同じ家族にもう一度参加すると、また見られます。」、「キャンセル」と「抜ける」（赤の文字）。

`family_delete_account_dialog`
- 背面は `family` の画面にする。
- 「CARTMATE」のバッジと、「週末の買い出しリスト」を例にした補足の枠は取り除く。
- 本文は「プライベートなリストと購入の記録を削除します。共有のリストは家族に残ります。この操作は取り消せません。削除の前に、Google で再度ログインします。」。「キャンセル」と「削除する」（赤の文字）。

## 手順4: 確認と仕様書

ここから

これで13画面がそろいました。まず、すべての画面が「デザインの値」と、手順1〜3で指示した内容のとおりになっているかを確認し、食い違っている画面があれば直してください。そのあとで、`family_screens_spec.md` を1つ書き出してください。実装者がこの文書と画面の画像だけで Jetpack Compose で再現できる粒度にします。構成は次のとおりです。

1. 画面一覧
   - 表（画面名、役割、どの状態を描いたものか）。login、family_onboarding、family_onboarding_removed、list_overview、join_code_entry、join_code_entry_error、join_confirm、join_confirm_expired、join_confirm_merge、family、family_solo、family_leave_dialog、family_delete_account_dialog の13画面をこの順に並べる。
2. 画面ごとの仕様（画面名を見出しにして、1画面ずつ）
   - 上から順に、構成要素とその文言。
   - 文字の大きさと太さ、色（「デザインの値」の色コード）、角丸、余白。
   - 使う部品（Material 3 / Jetpack Compose の標準コンポーネント名。例: `TopAppBar`、`OutlinedTextField`、`AlertDialog`）。
   - タップできる要素と、タップしたときに起きること。タップ領域が 48dp 以上であること。
   - 同じ画面の別の状態（エラー、期限切れ、自分しかいないときなど）で変わる点。
3. たたき台からの変更点
   - 手順1〜3で指示した内容に沿って変えた点と、それ以外に変えた点。それぞれの理由。
4. 追加した色
   - 破壊的な操作の赤など、「デザインの値」にない色を使った場合は、用途・色コードを表にする。ない場合は「追加なし」と書く。
