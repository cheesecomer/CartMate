# 画面と操作

## 見た目の基準

すべての画面がこの基準に従います。値は [design-tokens.md](../design-tokens.md)、画面ごとの仕様は [implementation-spec.md](../implementation-spec.md)、決定の経緯は [ui-design-decisions.md](../ui-design-decisions.md) にあります。見た目は [screens/](screens/) のモックを参考にします。資料どうしで値が食い違う場合は、implementation-spec.md（家族とアカウントの画面は family-screens-spec.md） → design-tokens.md → ui-design-decisions.md → モック → [DESIGN.md](DESIGN.md) の順に優先します。

### 配色
- ブランドカラーはライラックパープル（`#6B4E8C`）です。完了・チェック・進捗・FAB を含め、緑は使いません（ライラックとの補色で浮いて見えるため）。
- 背景（surface / background）は淡いライラック（`#FFF7FF`）にします。アプリアイコンの背景・スプラッシュ画面の背景と同じ色にして、起動時に明暗が切り替わらないようにします。
- `ui/theme/Color.kt` の `lightColorScheme` には design-tokens.md の値を入れます。トークンにない役割（secondary、tertiary など）は、`#6B4E8C` から Material Color Utilities で生成した値を使います。
- **端末がダークモードでも明るい配色のままにします。** ダーク用の配色は持ちません。ステータスバーとナビゲーションバーのアイコンも、常に濃い色にします（`MainActivity` の `enableEdgeToEdge`）。
- **端末の壁紙に合わせた配色（Dynamic Color）は使いません。** ブランドの印象が端末ごとにばらつくためです。
- 色は `MaterialTheme.colorScheme` の役割（primary、errorContainer など）で指定し、色の値を直接書きません。役割にない色（オフラインバナーの `WarningBannerBackground` / `WarningBannerText`、完了した文字の `TextDisabled`）は、`ui/theme` に名前を付けて置きます。

### 文字
- フォントは端末の標準（`FontFamily.Default`。日本語は Noto Sans CJK JP、英数字は Roboto）を使います。DESIGN.md の Epilogue / Plus Jakarta Sans は日本語の字形を持たないため使いません。
- 大きさと太さは design-tokens.md の `CartMateTypography` に従います（画面タイトル 22sp、リスト名・商品詳細の品名 18sp Bold、商品名 16sp Bold など）。

### 形と余白
- 余白は 8dp を基本単位にします（4 / 8 / 12 / 16 / 24dp）。画面の左右は 16dp です。タップできる部品は 48dp 以上にします。
- 角丸は、チップ 8dp、入力欄 12dp、カード 16dp、ボトムシートとダイアログ 28dp、FAB・主要ボタン・数量のバッジは完全な丸（pill）にします。
- カードは影を付けず、`outlineVariant` の 1dp の線で区切ります。FAB は Material 3 の標準の影を使います。ドラッグ中のカードだけ、影を付けて持ち上がっているように見せます。

### 部品
- リスト一覧のカードは `ui/lists/ListCard`、リスト詳細の項目のカードは `ui/listdetail/ItemCard` で組みます。カードに付けたタップや TalkBack 用のアクションと読み上げ要素が分かれないよう、Material 3 の `ListItem` は使いません。
- 一度だけ知らせる結果（チェックした、削除したなど）は Snackbar で表示し、元に戻せるものには「元に戻す」を付けます。
- 確認が必要な操作（リストの削除）にだけ、ダイアログを使います。
- 入力のまとまり（リストの作成、サジェスト）はボトムシート（背景は `surfaceContainerLowest`、上部の角丸 28dp）にします。どちらも開くと入力欄にフォーカスしてソフトキーボードを出すので、シートはキーボードと一緒に画面の下からせり上がり、キーボードの上端に付いて止まるようにします（`ui/components/KeyboardSheet`）。シートが先に出て止まり、あとからキーボードに押し上げられる（カクついて見える）ことはありません。
  - キーボードの動きに合わせて1フレームずつ動かすため、`ModalBottomSheet`（別のウィンドウ）ではなく、画面の上に重ねて表示します。出す前のシートは画面の下に隠して配置しておき、入力欄にフォーカスできるようにします。
  - キーボードが出始めないまま1秒たった場合（物理キーボードなど）は、キーボードなしでシートだけを出します。
  - 幕のタップ・戻るキー・下へのドラッグで閉じます。
- リストや商品ごとの装飾アイコンは置きません。アイコンは状態（鍵、未同期、オフライン）と操作のボタンにだけ使います。
- アイコンは Material Icons のパスから、使う分だけベクター画像として `res/drawable` に置きます（Material 3 1.4 にはアイコン集が含まれないため）。

### アプリアイコンとスプラッシュ
- 背景は `#FFF7FF`、絵柄は `#6B4E8C` のショッピングカートとチェックマークです。枠や縁取りは付けません（`res/drawable/ic_launcher_foreground.xml`）。安全領域（中央の 66dp）いっぱいに描いた絵柄を、中心を基準に 80% に縮小し、左右の車輪の中間がアイコンの中心に来るよう左にずらして配置します（円形のマスクで縁に迫らないように）。
- テーマアイコン（Android 13 以降の単色表示）にも、同じ形を使います。
- Android 12 以降の SplashScreen は、`windowSplashScreenBackground` を `#FFF7FF` にします（[implementation-spec.md](../implementation-spec.md) §5）。

## リスト一覧

- 上部のバーは、左にアプリ名「CartMate」、右端に自分のアカウントのアバターです。アバターのタップで家族画面を開きます（[家族とアカウント](#家族とアカウント)）。
- オフラインバナー、「長押しで並び替えができます」（リストが1件以上のとき）、2列のカード（`LazyVerticalGrid`）の順に並べます。
- カードの中身: リスト名（18sp Bold。長ければ省略）と、プライベートのリストなら鍵アイコン（メンバーのアバターは出さない。メンバーはどのリストでも同じため）。2行目に備考。下部に件数（「5 件 のこり」の数字を primary で大きく）と進捗バー（primary / トラック `surfaceContainer`）。
- 状態ごとの件数の表示は [要件](../requirements.md) §3.1 のとおりです。「登録なし」と「買い終わった！」の数字は `onSurfaceVariant` にします。
- 右下に Extended FAB「＋ リスト作成」。タップでリスト作成のボトムシート（リスト名、公開範囲「共有リスト／プライベート」、メモ、「作成する」）を開きます。
- 空の状態は、画面中央に「リストがありません」（20sp Bold）、「最初の買い物リストを作成しましょう」（14sp）、「＋ リストを作成する」ボタンを置きます。
- 文字サイズ 200% では、カードの高さを中身に合わせて伸ばし、リスト名は2行まで表示してから省略します。

## リスト詳細の画面構成

```
┌───────────────────────────┐
│ TopBar: ← リスト名 （🔒）    ⋮ │
│ [オフラインバナー]           │
│ LazyColumn                 │
│ ［のこり N件 / M完了］          │
│   「カードをタップして購入完了」  │
│   項目カード（名前 数量, 備考）  │
│   ※ 完了は元の位置で打ち消し線   │
├───────────────────────────┤
│ 商品追加欄（常時表示）        │ ← フォーカスでサジェストのシートを開く
└───────────────────────────┘
```

- TopBar の ⋮ メニューは「リストを編集」（リスト名と備考を変えるダイアログ）と「リストを削除」です。「リストを削除」は未購入が0件のときだけ有効にし、それ以外は無効の理由を Snackbar で伝えます。オフラインでも削除できます。
- 項目は並び順（`sortKey`）に並べ、新しい項目は末尾に追加します。チェックした項目は別の場所に移さず、元の位置のまま示します（チェック直後に行が移動すると、続けて操作するときに位置がずれて誤操作しやすいため）。チェックから24時間が過ぎた項目は表示しません。
- 未購入の項目のカード: 背景 `surfaceContainerLowest`。商品名（16sp Bold）、数量・単位のバッジ（背景 `primaryContainer`、文字 primary）、共有のリストのプライベートな項目なら鍵アイコン、2行目に備考。右端に「編集」「削除」のアイコンボタン（`onSurfaceVariant`）。ボタンの読み上げ名には商品名を含めます（例: 「牛乳を削除」）。
- 完了した項目のカード: 背景 `surfaceContainerLow`。商品名は打ち消し線と `TextDisabled`（`onSurface` の 40%）。2行目にチェックの印（primary）と「花子 10:02」。右端に「元に戻す」の OutlinedButton。名前は `members` の displayName から引きます。
- 未同期の項目には、2行目の末尾に小さな「未同期」アイコンを付けます。
- 未購入の項目とチェック済みの項目は、Repository から1つの一覧（`observeListItems`）として受け取ります。別々に受け取ると、チェックした瞬間に同じ項目が両方に含まれる状態が一瞬生じるためです。
- 進捗の「M完了」は、画面に表示している完了の項目（直近24時間）の数です。

## 商品の追加

### 商品追加欄とサジェストのシート

画面下部の商品追加欄はシートを開くための入口です。タップすると、シートの入力欄にフォーカスしてソフトキーボードを出し、シートはキーボードと一緒に画面の下からせり上がって、キーボードの上端に付いて止まります（キーボードの表示アニメーションに合わせて1フレームずつ動かす）。シートがキーボードより先に出て止まり、あとから押し上げられることはありません。キーボードが出始めないまま1秒たった場合（物理キーボードなど）は、キーボードなしでシートだけを出します。キーボードが出きったあとは、キーボードを閉じてもシートは表示したままにします。背面は半透明の幕（`scrim`）で覆い、幕のタップ・戻るキー・シートの下へのドラッグで閉じます。

共有のリストでは、シートの入力欄の下に「公開範囲 ［全員に共有］［🔒自分のみ］」のチップを表示し、Enter と「＋」で追加するときの公開範囲を示します（[要件](../requirements.md) §3.4）。チップで切り替えると、そのリストの直前の公開範囲として覚えます。プライベートのリストでは表示しません。
```
┌───────────────────────────┐
│ ─── （つまみ）               │
│ 🔍 商品名 [入力欄]        ✕  │
│ ⚙ 数量を設定して追加      ＞ │ ← 入力中だけ
│ 候補（名前 / 補足）       ＋ │
│ 候補                     ＋ │
└───────────────────────────┘
```

- 未入力のときは時期が近い商品（補足「約14日ごと・最後は16日前」）、入力中は補完候補（「追加済み」、早すぎる再購入なら「前回 10/18 に購入・いつもは約14日ごと」）を、1つの一覧で表示します。時期が近い商品を出せないリストでは「商品名を入力すると候補が出ます」とだけ表示します。
- 候補の行は、名前の部分と右端の「＋」（48dp の丸いボタン、primary）でタップの意味が違います。

`domain` モジュールの純粋な reducer（`AddItemReducer`）として実装し、JVM で全遷移をテストします。

```kotlin
sealed interface AddItemState {
    data class Idle(val text: String) : AddItemState   // シートを閉じている。商品追加欄に下書きを残す
    data class Open(val text: String) : AddItemState   // シートを開いている。空なら時期が近い商品、入力中なら補完
    data class Entering(val text: String) : AddItemState   // 商品詳細入力画面を開いている。戻ったらシートを開き直す
}
```

| 現在 | イベント | 次 | 副作用 |
|---|---|---|---|
| Idle | 商品追加欄にフォーカス | Open（下書きを引き継ぐ） | シートを開き、入力欄にフォーカス |
| Open | 文字入力 | Open | |
| Open | IME Enter/Done（空白以外） | Open（空） | 数量1・単位「個」・直前の公開範囲で項目を追加 |
| Open | IME Enter/Done（空） | 変化なし | |
| Open | 候補の「＋」 | Open（空） | 候補の前回の数量・単位（なければ 1・「個」）・直前の公開範囲で追加 |
| Open | 候補の名前をタップ | Entering（入力文字は保持） | 候補の内容で商品詳細入力画面へ |
| Open | 「数量を設定して追加」（空白以外） | Entering（入力文字は保持） | 入力した商品名・数量1・単位「個」で商品詳細入力画面へ |
| Open | 戻るキー・幕のタップ・下へスワイプ | Idle（入力文字は保持） | シートを閉じる |
| Entering | 追加して戻った | Idle（空） | |
| Entering | 追加せずに戻った（✕・戻るキー） | Open（入力文字は保持） | シートを開き直す |

- 商品詳細入力画面の結果（追加した・やめた・編集が拒否された）は、リスト詳細の `NavBackStackEntry.savedStateHandle` に渡します（`CartMateNavHost` の `closeEntry` / `rememberEntryResults`）。
- サジェストのシートは、共通の `KeyboardSheet` の中に入力欄と候補を置いたものです（`AddItemSheet`。「部品」を参照）。

- 追加は非同期の結果を待ちません（オフラインでもキューに積まれる）。そのため連続入力が止まりません。
- Enter と「＋」は、表記ゆれの選択肢を出しません。正規化名が一致する既存の商品があればそれを使い、なければ新しい商品を作ります。

### 商品詳細入力画面

Navigation の独立した画面（`ui/itementry`）です。新規の追加と、未購入の項目の編集に使います。

| 要素 | 新規 | 編集 |
|---|---|---|
| タイトル | 商品の詳細入力 | 商品の編集 |
| 追加先 | 「追加先: スーパー（共有リスト 3人）」 | 同じ |
| 商品名 | 入力した名前・候補の名前 | 項目の名前 |
| 前回の購入 | 「前回: 1パック（10/18 購入・約14日ごと）」。早すぎる再購入なら注意の文言 | 表示しない |
| 数量 | 初期値1。数字のタップで直接入力、「−」「＋」で1ずつ（1未満にはしない） | 項目の数量 |
| 単位 | 候補の前回の単位、なければ「個」。チップ「個」「本」「パック」「袋」と自由入力 | 項目の単位 |
| 公開範囲 | 共有のリストだけ「全員に共有」「自分のみ」。初期値は直前の公開範囲 | 現在の値を表示するだけ |
| 備考 | 空。過去にその商品に付けた備考を3件までチップで出す | 項目の備考 |
| 表記ゆれ | 新しい商品名で似た商品があれば「『牛乳』と同じ商品として記録する」 | 表示しない |
| 確定 | 「リストに追加する」→ 追加してリスト詳細へ | 「更新する」→ 更新してリスト詳細へ |
| ✕・戻るキー | サジェストのシートに戻る（入力文字は保持） | リスト詳細に戻る |

- 入力状態は `domain` の純粋な関数（`ItemEntryState` と検証）として持ちます。商品名が空、数量が0以下や数値でないときは確定ボタンを無効にします。単位と備考は空でもかまいません。
- 公開範囲を選んで追加すると、そのリストの「直前の公開範囲」を更新します。値はリストごとに ViewModel より長く生きるインメモリのストア（`LastVisibilityStore`、Hilt の Singleton）に持ち、アプリを起動し直すと「共有」に戻ります。
- 編集中に他のメンバーがその項目をチェックまたは削除した場合の表示は [sync.md](sync.md#競合の振る舞い) のとおりです。

## 他のメンバーによるチェックの通知

別々の店で買い物をしていると、同じ商品を二重に買ってもアプリ上では気づけません。二重購入そのものは防げないため、**買った直後に気づける**ようにします。

| 状況 | 表示 |
|---|---|
| 自分のチェックが `AlreadyCompleted` になった（オフラインでしたチェックが、接続後に拒否された場合を含む） | Snackbar「牛乳は 花子さんが 10:02 にチェック済みです」 |
| リスト詳細を開いている間に、他のメンバーがこのリストの項目をチェックした | Snackbar「花子さんが牛乳をチェックしました」 |
| 上記を見逃した場合 | チェック済みの項目に、チェックした人と時刻が表示されている |

- 他のメンバーによるチェックは、未購入項目の購読で「open から消えた」項目のうち、`completedBy != 自分` のものとして検出します。チェックした人を知るには項目を読む必要がありますが、リスト詳細の購読（直近24時間のチェック済みを含む）に含まれるので、読み取りは増えません。
- プライベートな項目は本人にしか見えないので、通知の対象になりません。
- チェックはカゴに入れた時点で行われるのが普通なので、オンラインであれば通知は会計の前に届き、二重に取ったものを棚に戻せます。オフラインの間は、接続が戻るまで通知が遅れます。
- **まとめて表示する**: 同じ店で手分けして買っているとうるさくなるため、約3秒ごとにまとめて表示します（例: 「花子さんが牛乳ほか2件をチェックしました」）。
- 対象は、画面を開いている間に起きた変更だけです。画面を開いた時点ですでにチェック済みだった項目は通知しません。
- 自分の Undo Snackbar と重なった場合は、Undo Snackbar を優先し、他のメンバーの通知はそのあとに表示します。
- 2件目の購入は記録しません。周期の計算では同じ日の購入を1回にまとめるため、記録しても予測は変わりません。

## スワイプ操作

「→ チェック、← 取り消し」で統一します。

| 場所 | → スワイプ | ← スワイプ |
|---|---|---|
| 未チェックの項目 | チェックする | 項目を削除する（誤って追加したものの取り消し） |
| チェック済みの項目 | なし | チェックを外す（Undo と同じ） |

- 誤って追加した項目を削除できないと、誤入力を「チェック」で消すしかなくなり、購入履歴が汚れて予測が狂います。そのため、未購入の項目は削除できるようにしています。
- 実装には Compose の `SwipeToDismissBox` を使います。行の幅の約40%を超えてから離すと確定します。スワイプ中は背景に色とアイコンを表示します（→ は primary とチェックマーク、← は error とゴミ箱。チェック済みの項目の ← は primary と元に戻すアイコン）。緑は使いません。
- **削除の取り消し**: 削除したら Snackbar「牛乳を削除しました ［元に戻す］」を表示します。元に戻すと、同じ itemId・同じ内容・同じ並び順の値で項目を作り直すので、削除する前の位置に戻ります。
- **削除はオフラインでも可能**です（Firestore の書き込みキュー）。
- **誤操作の防止**: 縦スクロールの最中に横スワイプが反応しないよう、横方向の移動量が十分大きいときだけスワイプとして扱います（`SwipeToDismissBox` の標準動作）。確定までの距離は、実機で試して調整します。
- **ボタン**: スワイプは気づきにくく、操作に慣れも要るため、行の右端にボタンも置きます。未購入の項目は「編集」（鉛筆）と「削除」（ゴミ箱）、チェック済みの項目は「元に戻す」です。チェックのボタンは置かず、タップかスワイプで行います。
- **タップ**: 項目のタップは、チェックの切り替えです（未購入はチェック、チェック済みはチェックを外す）。編集は「編集」ボタンからだけ行います。
- **アクセシビリティ**: TalkBack では、カードをダブルタップするとチェックの切り替えになり、「チェック」「チェックを外す」と操作内容が読み上げられます（`clickable` の `onClickLabel`）。
- **状態を保存しない**: `rememberSwipeToDismissBoxState` は状態を `rememberSaveable` で保存します。LazyColumn は行が消えたあとも保存した状態をキーごとに保持するため、元に戻した項目が「スワイプ確定済み」の状態で復元され、チェックや削除がもう一度実行されてしまいます。そのため `SwipeToDismissBoxState` を `remember` で作り、`onDismiss` には同じ関数を渡し続けます（`onDismiss` が変わると呼び直されるため）。

## 並び替え

- リストと項目は、ロングタップで持ち上げ、ドラッグで並べ替えます。ライブラリ `sh.calvin.reorderable` の `ReorderableItem` と `longPressDraggableHandle` を使います（Compose に標準の並び替えの部品がないため）。リスト一覧は2列のグリッド（`LazyVerticalGrid`）、リスト詳細は1列（`LazyColumn`）です。
- カードにドラッグハンドルは置きません。リスト一覧では「長押しで並び替えができます」と文字だけで案内します。
- ドラッグ中は画面上の並びだけを入れ替え、指を離したときに、動かした1件の前後の項目を Repository に渡して確定します（`moveList` / `moveItem`）。ドラッグ中に毎回書き込まないためです。
- 項目の左右のスワイプとは、指の向きで区別します。ロングタップしてから動かすとドラッグ、すぐに横に動かすとスワイプです。
- ドラッグ中のカードは、影を付けて持ち上がっているように見せます。
- TalkBack ではドラッグできないため、カスタムアクションを登録します。リスト一覧は「前へ移動」「後ろへ移動」、リスト詳細は「上へ移動」「下へ移動」です。

## 家族とアカウント

振る舞いは [要件](../requirements.md) §3.5 のとおりです。見た目は [family-screens-spec.md](../family-screens-spec.md) と、[screens/](screens/) の `login`、`family-*`、`join-*` のモックに合わせます。

### 最初に表示する画面

起動時と状態が変わったときに、ログインと所属家族（`users/{uid}.householdId`）から表示する画面を決めます。

| 状態 | 画面 |
|---|---|
| ログインしていない | ログイン |
| ログインしていて、家族に参加していない | 家族の作成・参加 |
| 家族に参加している | リスト一覧 |

- 表示中に家族から外された（自分の `members` が消えた）場合は、「家族の作成・参加」に移り、「共有が取り消されました」と表示します。
- 招待リンク（`/join/{code}`）から起動した場合は、コードを覚えておき、ログインのあとで参加の確認画面を開きます。自分しかいない家族に参加している場合は合流の確認画面を、ほかのメンバーがいる家族に参加している場合は「すでに家族に参加しています」を表示します。
