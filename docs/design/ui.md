# 画面と操作

## リスト詳細の画面構成

```
┌───────────────────────────┐
│ TopBar: リスト名            │
│ [オフラインバナー]           │
│ LazyColumn                 │
│   未購入項目（チェック, 名前, 数量単位）│
│   ▸ チェック済み（直近24時間）※折りたたみ │
├───────────────────────────┤
│ サジェストパネル（入力欄の上） │ ← フォーカス中だけ表示
├───────────────────────────┤
│ 入力バー（常時表示）          │ ← imePadding() でキーボードの直上に固定
└───────────────────────────┘
```

- `enableEdgeToEdge()` と、入力バーへの `Modifier.imePadding()` でキーボードに追従させます。サジェストは入力欄の **上** に出すので、キーボードに隠れません。
- サジェストパネルの高さは候補の件数に合わせて変わり、最大で「TopBar・オフラインバナーより下で、入力バーとキーボードより上の領域すべて」まで広がります。広がった分は項目リストの上に重ねて表示します。キーボードが出ていると表示領域が狭くなるため、候補を多く見せることを優先しています。TopBar とオフラインバナーは、オフライン状態が分かるよう隠しません。
- チェック済みセクションの各行には、チェックした人と時刻を表示します（例: 「牛乳 ✓ 花子 10:02」）。名前は `members` の displayName から引きます。

## 商品追加の入力状態

ViewModel 内で、純粋な reducer（`(State, Event) -> State`）として実装し、JVM で全遷移をテストします。

```kotlin
sealed interface AddItemState {
    data class Idle(val text: String) : AddItemState                        // 未フォーカス
    data object FocusedEmpty : AddItemState                                 // フォーカス中・未入力 → 時期が近い商品
    data class Typing(val text: String) : AddItemState                      // 入力中 → 名前の補完
    data class Detail(                                                      // 数量・単位入力（インライン展開）
        val name: String,
        val product: ProductRef?,          // 既存商品と一致 or 候補選択。null は新規
        val quantity: String,              // 初期値 "1"
        val unit: String,                  // 前回の単位、なければ ""
        val notice: EarlyPurchaseNotice?,  // 早すぎる再購入の注意（表示のみ）
        val similar: List<ProductRef>,     // 表記ゆれ候補（suggestions.md）
        val linkTo: ProductRef?,           // ユーザーが「同じ商品」を選んだ場合
    ) : AddItemState
}
```

| 現在 | イベント | 次 | 副作用 |
|---|---|---|---|
| Idle | 入力欄にフォーカス | 入力欄が空なら FocusedEmpty、空でなければ Typing | |
| FocusedEmpty / Typing | 文字入力 | 空なら FocusedEmpty、空でなければ Typing | |
| FocusedEmpty / Typing | フォーカスを失う・戻るキー | Idle（入力文字は保持） | サジェストを隠す |
| Typing | IME Enter/Done（空白以外） | Detail | 名前から product を解決し、前回の単位と注意表示を計算 |
| FocusedEmpty | IME Enter | 変化なし | |
| FocusedEmpty / Typing | 候補をタップ | Detail | 候補の product で確定。**この時点では登録しない** |
| Detail | 数量欄の IME Done／「追加」ボタン | FocusedEmpty（名前欄にフォーカスを戻す） | 項目を追加 |
| Detail | ✕／戻るキー | Typing（名前を戻す） | |
| Detail | フォーカスを失う | Detail のまま（下書きを保持） | サジェストはもともと表示しない |

- **Detail に入ると数量欄（`KeyboardType.Decimal`, `ImeAction.Done`）にフォーカスします。** 最速の操作は「名前を入力 → Enter → Enter」です。単位欄はタップで編集し、直近の単位をチップで数個出します。
- 数量が空なら `null`（未指定）として登録します。0以下や数値でない値のときは確定ボタンを無効にします。
- 追加は非同期の結果を待ちません（オフラインでもキューに積まれる）。そのため連続入力が止まりません。

## 他のメンバーによるチェックの通知

別々の店で買い物をしていると、同じ商品を二重に買ってもアプリ上では気づけません。二重購入そのものは防げないため、**買った直後に気づける**ようにします。

| 状況 | 表示 |
|---|---|
| 自分のチェックが `AlreadyCompleted` になった（保留チェックの確定時を含む） | Snackbar「牛乳は 花子さんが 10:02 にチェック済みです」 |
| リスト詳細を開いている間に、他のメンバーがこのリストの項目をチェックした | Snackbar「花子さんが牛乳をチェックしました」 |
| 上記を見逃した場合 | チェック済みセクションで、チェックした人と時刻を確認できる |

- 他のメンバーによるチェックは、未購入項目の購読で「open から消えた」項目のうち、`completedBy != 自分` のものとして検出します。チェックした人を知るには項目を読む必要がありますが、チェック済みセクションの購読（直近24時間）に含まれるので、読み取りは増えません。
- チェックはカゴに入れた時点で行われるのが普通なので、オンラインであれば通知は会計の前に届き、二重に取ったものを棚に戻せます。オフラインの間は、接続が戻るまで通知が遅れます。
- **まとめて表示する**: 同じ店で手分けして買っているとうるさくなるため、約3秒ごとにまとめて表示します（例: 「花子さんが牛乳ほか2件をチェックしました」）。
- 対象は、画面を開いている間に起きた変更だけです。画面を開いた時点ですでにチェック済みだった項目は通知しません。
- 自分の Undo Snackbar と重なった場合は、Undo Snackbar を優先し、他のメンバーの通知はそのあとに表示します。
- 2件目の購入は記録しません。周期の計算では同じ日の購入を1回にまとめるため、記録しても予測は変わりません。

## スワイプ操作

「→ チェック、← 取り消し」で統一します。

| 場所 | → スワイプ | ← スワイプ |
|---|---|---|
| 未チェックの項目 | チェックする（チェックボックスのタップと同じ） | 項目を削除する（誤って追加したものの取り消し） |
| チェック済みセクションの項目 | なし | チェックを外す（Undo と同じ） |

- 誤って追加した項目を削除できないと、誤入力を「チェック」で消すしかなくなり、購入履歴が汚れて予測が狂います。そのため、未購入の項目は削除できるようにしています。
- 実装には Compose の `SwipeToDismissBox` を使います。行の幅の約40%を超えてから離すと確定します。スワイプ中は背景に色とアイコンを表示します（→ は緑とチェックマーク、← は赤とゴミ箱。チェック済みセクションの ← は元に戻すアイコン）。
- **削除の取り消し**: 削除したら Snackbar「牛乳を削除しました ［元に戻す］」を表示します。元に戻すと、同じ itemId・同じ内容で項目を作り直します。`createdAt` は作り直した時刻になるため、並び順は末尾に変わります。
- **削除はオフラインでも可能**です（Firestore の書き込みキュー）。保留チェック中の項目は削除できないようにし、← スワイプは保留チェックの取り消し（チェックを外す）として扱います。
- **誤操作の防止**: 縦スクロールの最中に横スワイプが反応しないよう、横方向の移動量が十分大きいときだけスワイプとして扱います（`SwipeToDismissBox` の標準動作）。確定までの距離は、実機で試して調整します。
- **アクセシビリティ**: スワイプだけに頼りません。チェックボックスは残し、TalkBack 用に「チェック」「削除」をカスタムアクションとして登録します。
