# 画面と操作

## 見た目の基準

すべての画面がこの基準に従います。

### 配色
- ブランドカラーはグリーン（`#2E7D4F`）です。Material Color Utilities（TonalSpot、2021年版の仕様）で、Material 3 の配色を生成しています（`ui/theme/Color.kt`）。
- **白を基調にします。** 背景（background / surface）は白にし、クリーンな印象にします。
- **端末がダークモードでも白のままにします。** ダーク用の配色は持ちません。ステータスバーとナビゲーションバーのアイコンも、常に濃い色にします（`MainActivity` の `enableEdgeToEdge`）。
- **端末の壁紙に合わせた配色（Dynamic Color）は使いません。** ブランドの印象が端末ごとにばらつくうえ、スワイプの色との組み合わせも予測できなくなるためです。
- 色は `MaterialTheme.colorScheme` の役割（primary、errorContainer など）で指定し、色の値を直接書きません。

### 影と区切り
- 影や、影の代わりに付く色（tonal elevation）は使わず、区切りが必要なところは `outlineVariant` の細い線にします。
- 一覧の行の間には区切り線を引かず、余白で区切ります。

### 部品
- 一覧の行の中身は `ui/components/CardContent` で組み、高さと余白は Material 3 の `ListItem` と同じ（1行 56dp、2行 72dp、左右 16dp）にします。`ListItem` 自体は使いません。`ListItem` は中身を独立した読み上げ要素にまとめるため、カードに付けたタップや TalkBack 用のアクションと別の要素になってしまうからです。リストとリスト詳細の項目は、1件ずつ角丸のカード（`surfaceContainerLow`、角丸 8dp、カードの間 8dp）にし、左端の帯（幅 12dp）の色で状態を示します（共通の部品 `ui/components/AccentCard`）。帯は、これから対応するもの（未購入の項目、未購入があるリスト、まだ何も買っていない新しいリスト）は primary、済んだもの（チェック済みの項目、買い終わったリスト）は outlineVariant にします。新しいリストを済んだものと同じグレーにすると、作った直後なのに終わったように見えるためです。主な文字を1行目、補足（数量・単位、未購入件数など）を2行目に置きます。
- 行ごとの操作は、右端のアイコンボタン（`IconButton`、色は `onSurfaceVariant`）で行えるようにします。
- 空の状態は、画面中央に `onSurfaceVariant` の色の1文で示します。
- 一度だけ知らせる結果（チェックした、削除したなど）は Snackbar で表示し、元に戻せるものには「元に戻す」を付けます。
- 確認が必要な操作（リストの削除など）にだけ、ダイアログを使います。
- アイコンは Material Icons のパスから、使う分だけベクター画像として `res/drawable` に置きます（Material 3 1.4 にはアイコン集が含まれないため）。

### アプリアイコン
- 白い背景に、ブランドカラーの線でカートとチェックマークを描きます。枠や縁取りは付けません（`res/drawable/ic_launcher_foreground.xml`）。安全領域（中央の 66dp）いっぱいに描いた絵柄を、中心を基準に 80% に縮小し、左右の車輪の中間がアイコンの中心に来るよう左にずらして配置します（円形のマスクで縁に迫らないように）。
- テーマアイコン（Android 13 以降の単色表示）にも、同じ形を使います。

## リスト詳細の画面構成

```
┌───────────────────────────┐
│ TopBar: リスト名            │
│ [オフラインバナー]           │
│ LazyColumn                 │
│   項目（名前, 数量単位）        │
│   ※ チェック済みは元の位置で打ち消し線 │
├───────────────────────────┤
│ サジェストパネル（入力欄の上） │ ← フォーカス中だけ表示
├───────────────────────────┤
│ 入力バー（常時表示）          │ ← imePadding() でキーボードの直上に固定
└───────────────────────────┘
```

- `enableEdgeToEdge()` と、入力バーへの `Modifier.imePadding()` でキーボードに追従させます。サジェストは入力欄の **上** に出すので、キーボードに隠れません。
- サジェストパネルの高さは候補の件数に合わせて変わり、最大で「TopBar・オフラインバナーより下で、入力バーとキーボードより上の領域すべて」まで広がります。広がった分は項目リストの上に重ねて表示します。キーボードが出ていると表示領域が狭くなるため、候補を多く見せることを優先しています。TopBar とオフラインバナーは、オフライン状態が分かるよう隠しません。
- チェックボックスは置きません。チェックはスワイプで行い、チェック済みの項目は打ち消し線で示します。
- 項目は並び順（`sortKey`）に並べ、新しい項目は末尾に追加します。チェックした項目は別の場所に移さず、元の位置のまま打ち消し線とグレーアウト（文字の透明度 38%。Material 3 で使えない状態を表すときと同じ）で示します（チェック直後に行が移動すると、続けてスワイプするときに位置がずれて誤操作しやすいため）。チェックから24時間が過ぎた項目は表示しません。
- 未購入の項目とチェック済みの項目は、Repository から1つの一覧（`observeListItems`）として受け取ります。別々に受け取ると、チェックした瞬間に同じ項目が両方に含まれる状態が一瞬生じるためです。
- チェック済みの項目には、チェックした人と時刻を表示します（例: 「牛乳 ✓ 花子 10:02」）。名前は `members` の displayName から引きます。

## 商品追加欄の状態

`domain` モジュールの純粋な reducer（`AddItemReducer`）として実装し、JVM で全遷移をテストします。商品追加欄は、項目の編集にも使います。

```kotlin
sealed interface AddItemState {
    data class Idle(val text: String) : AddItemState                        // 未フォーカス
    data object FocusedEmpty : AddItemState                                 // フォーカス中・未入力 → 時期が近い商品
    data class Typing(val text: String) : AddItemState                      // 入力中 → 名前の補完
    data class Detail(                                                      // 数量・単位入力（インライン展開）
        val name: String,
        val product: ProductRef?,          // 既存商品と一致 or 候補選択。null は新規
        val quantity: String,              // 初期値 "1"
        val unit: String,                  // 前回の単位、なければ ""
        val notice: EarlyPurchaseNotice?,  // 早すぎる再購入の注意（表示のみ）
        val similar: List<ProductRef>,     // 表記ゆれ候補（suggestions.md）
        val linkTo: ProductRef?,           // ユーザーが「同じ商品」を選んだ場合
    ) : AddItemState
    data class Editing(                                                     // 既存の項目の編集
        val itemId: ItemId,
        val name: String,
        val quantity: String,
        val unit: String,
        val draft: String,                 // 編集前に商品名の欄にあった文字。編集後に戻す
    ) : AddItemState
}
```

| 現在 | イベント | 次 | 副作用 |
|---|---|---|---|
| Idle | 入力欄にフォーカス | 入力欄が空なら FocusedEmpty、空でなければ Typing | |
| FocusedEmpty / Typing | 文字入力 | 空なら FocusedEmpty、空でなければ Typing | |
| FocusedEmpty / Typing | フォーカスを失う・戻るキー | Idle（入力文字は保持） | サジェストを隠す |
| Typing | IME Enter/Done（空白以外） | Detail | 名前から product を解決し、前回の単位と注意表示を計算 |
| FocusedEmpty | IME Enter | 変化なし | |
| FocusedEmpty / Typing | 候補をタップ | Detail | 候補の product で確定。**この時点では登録しない** |
| Detail | 数量欄の IME Done／「追加」ボタン | FocusedEmpty（名前欄にフォーカスを戻す） | 項目を追加 |
| Detail | ✕／戻るキー | Typing（名前を戻す） | |
| Detail | フォーカスを失う | Detail のまま（下書きを保持） | サジェストはもともと表示しない |
| すべて | 未購入の項目の「編集」ボタン | Editing（その項目の内容。入力途中の商品名は draft に残す） | 数量欄にフォーカス。数量入力の途中だった数量・単位は破棄する |
| Editing | 「更新」／IME Done | Idle（draft） | 項目を更新 |
| Editing | ✕／戻るキー | Idle（draft） | |

- **Detail に入ると数量欄（`KeyboardType.Decimal`, `ImeAction.Done`）にフォーカスします。** 最速の操作は「名前を入力 → Enter → Enter」です。単位欄はタップで編集し、直近の単位をチップで数個出します。
- 数量が空なら `null`（未指定）として登録します。0以下や数値でない値のときは確定ボタンを無効にします。
- 追加は非同期の結果を待ちません（オフラインでもキューに積まれる）。そのため連続入力が止まりません。

## 他のメンバーによるチェックの通知

別々の店で買い物をしていると、同じ商品を二重に買ってもアプリ上では気づけません。二重購入そのものは防げないため、**買った直後に気づける**ようにします。

| 状況 | 表示 |
|---|---|
| 自分のチェックが `AlreadyCompleted` になった（保留チェックの確定時を含む） | Snackbar「牛乳は 花子さんが 10:02 にチェック済みです」 |
| リスト詳細を開いている間に、他のメンバーがこのリストの項目をチェックした | Snackbar「花子さんが牛乳をチェックしました」 |
| 上記を見逃した場合 | チェック済みの項目に、チェックした人と時刻が表示されている |

- 他のメンバーによるチェックは、未購入項目の購読で「open から消えた」項目のうち、`completedBy != 自分` のものとして検出します。チェックした人を知るには項目を読む必要がありますが、リスト詳細の購読（直近24時間のチェック済みを含む）に含まれるので、読み取りは増えません。
- チェックはカゴに入れた時点で行われるのが普通なので、オンラインであれば通知は会計の前に届き、二重に取ったものを棚に戻せます。オフラインの間は、接続が戻るまで通知が遅れます。
- **まとめて表示する**: 同じ店で手分けして買っているとうるさくなるため、約3秒ごとにまとめて表示します（例: 「花子さんが牛乳ほか2件をチェックしました」）。
- 対象は、画面を開いている間に起きた変更だけです。画面を開いた時点ですでにチェック済みだった項目は通知しません。
- 自分の Undo Snackbar と重なった場合は、Undo Snackbar を優先し、他のメンバーの通知はそのあとに表示します。
- 2件目の購入は記録しません。周期の計算では同じ日の購入を1回にまとめるため、記録しても予測は変わりません。

## スワイプ操作

「→ チェック、← 取り消し」で統一します。

| 場所 | → スワイプ | ← スワイプ |
|---|---|---|
| 未チェックの項目 | チェックする | 項目を削除する（誤って追加したものの取り消し） |
| チェック済みの項目 | なし | チェックを外す（Undo と同じ） |

- 誤って追加した項目を削除できないと、誤入力を「チェック」で消すしかなくなり、購入履歴が汚れて予測が狂います。そのため、未購入の項目は削除できるようにしています。
- 実装には Compose の `SwipeToDismissBox` を使います。行の幅の約40%を超えてから離すと確定します。スワイプ中は背景に色とアイコンを表示します（→ は緑とチェックマーク、← は赤とゴミ箱。チェック済みの項目の ← は元に戻すアイコン）。
- **削除の取り消し**: 削除したら Snackbar「牛乳を削除しました ［元に戻す］」を表示します。元に戻すと、同じ itemId・同じ内容・同じ並び順の値で項目を作り直すので、削除する前の位置に戻ります。
- **削除はオフラインでも可能**です（Firestore の書き込みキュー）。保留チェック中の項目は削除できないようにし、← スワイプは保留チェックの取り消し（チェックを外す）として扱います。
- **誤操作の防止**: 縦スクロールの最中に横スワイプが反応しないよう、横方向の移動量が十分大きいときだけスワイプとして扱います（`SwipeToDismissBox` の標準動作）。確定までの距離は、実機で試して調整します。
- **ボタン**: スワイプは気づきにくく、操作に慣れも要るため、行の右端にアイコンのボタンも置きます。未購入の項目は「編集」（鉛筆）と「削除」（ゴミ箱）、チェック済みの項目は「チェックを外す」（元に戻す矢印）です。チェックのボタンは置かず、スワイプで行います。「編集」ボタンはオン・オフを切り替えるボタン（`IconToggleButton`）にし、編集中は primary の丸い背景で示します（行の背景色は変えない）。TalkBack でも選択中と伝わり、もう一度押すと編集をやめます。ボタンの読み上げ名には商品名を含めます（例: 「牛乳を削除」）。
- **タップ**: 項目のタップは、チェックの切り替えです（未購入はチェック、チェック済みはチェックを外す）。編集は「編集」ボタンからだけ行います。
- **アクセシビリティ**: TalkBack では、カードをダブルタップするとチェックの切り替えになり、「チェック」「チェックを外す」と操作内容が読み上げられます（`clickable` の `onClickLabel`）。
- **状態を保存しない**: `rememberSwipeToDismissBoxState` は状態を `rememberSaveable` で保存します。LazyColumn は行が消えたあとも保存した状態をキーごとに保持するため、元に戻した項目が「スワイプ確定済み」の状態で復元され、チェックや削除がもう一度実行されてしまいます。そのため `SwipeToDismissBoxState` を `remember` で作り、`onDismiss` には同じ関数を渡し続けます（`onDismiss` が変わると呼び直されるため）。

## 並び替え

- リストと項目は、ロングタップで持ち上げ、上下にドラッグして並べ替えます。ライブラリ `sh.calvin.reorderable` の `ReorderableItem` と `longPressDraggableHandle` を使います（Compose に標準の並び替えの部品がないため）。
- ドラッグ中は画面上の並びだけを入れ替え、指を離したときに、動かした1件の前後の項目を Repository に渡して確定します（`moveList` / `moveItem`）。ドラッグ中に毎回書き込まないためです。
- 項目の左右のスワイプとは、指の向きで区別します。ロングタップしてから動かすとドラッグ、すぐに横に動かすとスワイプです。
- ドラッグ中の項目は、影を付けて持ち上がっているように見せます。
- TalkBack ではドラッグできないため、「上へ移動」「下へ移動」をカスタムアクションとして登録します。
